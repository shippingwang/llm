# 第 6 章 偏好对齐

SFT 的训练方式是给模型提供问题和标准答案，让模型复刻参考回答的写法。但很多任务不存在唯一正确的答案。同一个输入，模型可以产出多份逻辑自洽的回答，它们之间的区别往往不在结论对错，而在表达完整度，简洁程度，推理严谨性，或是是否贴合用户全部要求。这类场景下，直接写出一份完美标准答案很难，但是标注者很容易对比两份回答，选出更好的那一个。

偏好优化就是利用这种两两比较的偏好信号完成模型对齐。本章按完整技术流展开：先构造偏好数据，再训练奖励模型，随后介绍 RLHF，GRPO 两类在线强化对齐方案，再讲解 DPO 这类离线直接偏好算法，最后统一梳理对齐过程中的典型失效模式。

## 6.1 偏好数据

偏好数据的基础单元是一组比较对：输入问题 \(x\)，一份胜出回答 \(y_w\)（chosen），一份落败回答 \(y_l\)（rejected）。
标注的核心前提：两份回答必须在完全相同的输入条件下对比，共用一套系统提示，用户问题，多轮对话上下文。标注只评判同等前提下两份输出的优劣。

> 
> 如果输出了额外的其他内容，哪怕这个内容没有错误，也是不符合指令要求的，标记为落败。

构造比较对有两种来源：让同一个模型对同一个问题多次采样生成候选，或是收集不同模型的输出，再交给标注者评审。人工标注适合判断表达清晰度，逻辑完整度这类主观标准；代码，数学这类可验证任务，可以先用程序执行结果做一层筛选，再对剩余主观部分做比较。使用大模型充当评审时，要把问题，候选，评判标准一同送入模型；为了规避位置偏见，需要随机调换两份回答的顺序，校验评审结果是否稳定。

标注过程允许存在平局，无法判断的样本。如果多名标注者意见不一致，应当保留分歧标记，而不是随机强行指定胜负。强行制造虚假胜负标签，会让模型学习没有依据的偏好。除了胜负结果，留存标注理由和数据来源也很有价值，后续模型出现风格偏向，格式偏好时，可以回溯原始标注查找原因。

比较对的样本质量有明确要求。两份回答不能差距悬殊：如果胜出回答是完整解答，落败回答是乱码，模型很容易区分，但学不到高质量回答之间细微的优劣边界。我们更需要收集模型本身已经可以生成的，质量接近的候选，对比它们在事实，推理，指令遵从层面的差距。同时要留意分布偏差：如果绝大多数胜出回答都更长，模型会单纯学会拉长文本；如果胜出样本全部来自同一个教师模型，模型只会模仿教师的措辞习惯。因此数据集里需要补充长度接近但质量不同的样本，也保留简短回答更优的案例。

同一个问题可以生成多组比较对，但是数据集划分时，同一个问题衍生的所有比较对，必须全部划入训练集或者全部划入验证集。一道题的四份回答可以组成六个比较对，它们共享同一个问题语义。如果拆分到训练，验证两个集合，验证集相当于间接泄露了问题信息，评估指标会虚高，无法反映模型处理全新问题的真实能力。

## 6.2 奖励模型（RM）

有了偏好对比数据之后，最经典的路线是先训练奖励模型。奖励模型的作用是给模型生成的回答输出标量分数，量化回答的好坏，作为后续强化学习的反馈源。

### 6.2.1 基础打分模型

一个普通语言模型读入问题和回答之后，会在每个位置输出词表 logits。如果我们希望它评价整份回答，可以保留原来的主干，把输出部分改成一个标量打分头。具体做法是，先把问题和回答按模板拼起来，取得最后一个有效位置的隐藏状态 \(h_{\mathrm{last}}\)，再计算：

\[
r_\phi(x,y) = w^\top h_{\mathrm{last}}+b
\]

这里 \(x\) 是问题，\(y\) 是回答，\(w\) 和 \(b\) 是打分头的权重与偏置。由于因果模型在最后一个有效位置可以读取前面的内容，这个位置能够把问题与回答的信息带到打分头。若隐藏宽度为 \(d\)，一批输入经过主干后得到 \([B,T,d]\) 的表示，我们按真实长度取出 \([B,d]\)，再映射为每条序列一个分数。

训练时，我们可以更新主干和打分头，也可以只更新部分参数或使用 LoRA。选择取决于当前表示能否支持评价任务，以及手里有多少标注数据。如果只是给冻结的主干接一个随机线性头，模型需要利用已有特征区分回答优劣；开放的参数越少，训练状态越省，但它能调整的判断方式也更有限。无论使用哪种方式，读取的末尾都应是回答的有效结束位置。序列右侧补齐之后，数组最后一格可能是 padding，因此要按真实长度和 attention mask 取值，并保持训练与评分时的结束符规则一致。

现在，我们有一对标注好的回答 \(y_w,y_l\)，希望模型给前者更高分。用 Bradley–Terry 假设，可以把分差转化为选择概率：

\[
P_\phi(y_w\succ y_l\mid x) = \sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right)
\]

两份回答同分时，模型预测的胜率为 0.5；如果优选回答高出 2 分，胜率约为 0.881。数据已经告诉我们优选回答获胜了，对这个事件取负对数似然，得到训练损失：

\[
\mathcal{L}_{\mathrm{RM}} = -\mathbb{E}_{(x,y_w,y_l)\sim D} \log\sigma(\Delta_\phi), \qquad \Delta_\phi = r_\phi(x,y_w)-r_\phi(x,y_l)
\]

我们对单个样本求导，可以看到优选分数的导数为 \(-\sigma(-\Delta_\phi)\)，另一份分数的导数为 \(\sigma(-\Delta_\phi)\)。梯度下降时，前者往上调整，后者往下调整；模型已经把优劣分得很开之后，这一对数据的梯度就会变小。若标注者之间存在分歧，也可以用实际选择比例作为软标签，训练模型预测这个比例。

实现时，把 \(B\) 个比较对拼成 \(2B\) 条序列，经过同一个主干和打分头，再按比较关系拆出 winner 分数和 loser 分数即可。每对的两条序列共享同一个问题，但回答长度可以不同，因此要分别保存有效位置。得到分数后，损失的核心只有一行 \(-\log\sigma(r_w-r_l)\)，难点更多在前面的数据和序列处理。

由于损失只使用分差，我们给同一问题下的所有回答都加上一个常数，训练结果不会改变。因此，用偏好对训练出来的分数，首先只有排序含义。要把它交给策略优化，我们还需要关注分数的尺度：如果奖励模型换了版本，原来相近的分差变得很大，同样的学习率和 KL 系数就可能产生不同更新。实际可以在固定样本上统计均值与波动，再做中心化或缩放，并把评分版本和变换一起固定。

### 6.2.2 过程奖励模型 PRM

只在回答结束后给分，反馈粒度粗，长推理场景缺陷明显。模型可能前面步骤全对，最后一步算错；也可能第一步读错题，后续全部跟着错。两条轨迹最终得分一样，训练无法区分二者问题。

过程奖励模型（Process Reward Model，PRM）把回答拆成多个推理步骤，在每个步骤边界做打分。设步骤序列为 \(z_1,\ldots,z_K\)，标签 \(c_k\) 表示第 \(k\) 步是否成立，模型给出的预测为 \(q_\phi(x,z_{\le k})\)，使用二元交叉熵损失：

\[
\mathcal{L}_{\mathrm{PRM}} = -\sum_k \left[ c_k\log q_\phi(x,z_{\le k}) + (1-c_k)\log\left(1-q_\phi(x,z_{\le k})\right) \right]
\]

公开代表数据集是 PRM800K，包含约 80 万步骤级反馈标签。逐步人工标注成本很高，也有方案通过续写采样，看后续成功率自动构造伪标签。但伪标签有偏差：一个正确但很难继续往下解的步骤，容易被打低分；带错误的前缀，也有可能后续碰巧修正。

拿到每一步分数之后，整条轨迹的聚合方式有多种：取最小值（看最差一步），平均值，概率乘积。不同聚合方式适合不同任务，没有统一最优解。如果把过程分数用于策略训练，还要注意避免模型单纯靠增加步骤堆砌总分。

### 6.2.3 可验证奖励 RLVR

很多任务不需要人工训练奖励模型，直接用程序校验结果作为奖励，也就是基于可验证奖励的强化学习（RLVR）。数学题提取答案比对，代码在隔离环境运行测试用例，都属于这类。

奖励可以组合多项指标：

\[
r = r_{\mathrm{correct}} +\lambda_f r_{\mathrm{format}} +\lambda_c r_{\mathrm{constraint}}
\]

\(r_{\mathrm{correct}}\) 评价答案正确性，\(r_{\mathrm{format}}\) 评价格式，\(r_{\mathrm{constraint}}\) 评价其他约束。要注意权重平衡，避免格式分权重过大，模型优先讨好格式而不追求正确。对于必须满足的要求，也可以先判断是否合格，再对合格回答细分质量，不允许其他高分抵消这个失败。

### 6.2.4 生成式评审

对于分析，写作和复杂指令，评分依据往往需要结合当前问题才能确定。我们可以让评审模型读取任务要求与候选回答，先写出逐项判断和相应证据，再给出分数或胜负。这类生成式评审使用语言模型输出评价过程，便于根据不同任务组织评分标准，也方便开发者核查它为什么给出某个结果。接入策略训练时，通常仍要把评价转换为明确的标量奖励，并固定提取与聚合规则。

DeepSeek-GRM 采用生成评价原则与批评意见的路线，并研究通过多次评审和结果聚合改善判断。生成过程提供了更多可以检查的信息，但评价文字同样可能误读要求或引用错误证据。因此，能够由程序确定的事实可以先交给验证器，其余部分再由模型按规则评审，并用人工确认的数据检查评分偏差。奖励系统参与了策略优化之后，还需要保留独立的验证任务，观察提高分数是否同时改善了实际回答。

## 6.3 RLHF 与 PPO

奖励模型训练完成之后，就进入 RLHF 的策略优化阶段。RLHF 的完整流程是：SFT 基座 → 偏好数据训练奖励模型 → PPO 强化学习更新策略。

语言模型是自回归策略。生成回答时，问题和已经写出的内容共同构成当前状态 \(s_t=(x,y_{<t})\)。模型预测下一个 token \(y_t\)，它输出的条件概率分布 \(\pi_\theta(y_t\mid s_t)\) 就是策略。
模型不断采样 token，追加到上下文，直到生成完整回答 \(y\)。之后奖励函数给出这条回答的分数 \(r(x,y)\)。我们的目标，是调整参数，提升高分回答出现的概率，等价于最大化期望奖励：

\[
J(\theta) = \mathbb{E}_{x\sim D,\ y\sim\pi_\theta(\cdot\mid x)} \big[r(x,y)\big]
\]

\(D\) 代表问题数据集。这里有一个关键特点：回答是当前模型自己采样出来的。参数一旦更新，模型分布就会变化，下一轮采样得到的回答集合也跟着改变，这是在线强化学习的核心特征。

奖励来自外部打分器或者程序校验，它不是模型内部可微的网络层，无法顺着采样过程直接反向传播。借助对数求导恒等式 \(\nabla p=p\nabla\log p\)，我们改写梯度：

\[
\nabla_\theta J = \mathbb{E}_{y\sim\pi_\theta} \left[ r(x,y)\,\nabla_\theta\log\pi_\theta(y\mid x) \right]
\]

整条回答的对数概率，按自回归链式分解：

\[
\log\pi_\theta(y\mid x) = \sum_{t=1}^{|y|} \log\pi_\theta(y_t\mid x,y_{<t})
\]

原始梯度方差很大，单次采样好坏会造成参数剧烈抖动。引入基线 \(b(x)\)，用优势 \(A=r-b\) 替代原始奖励。基线只和输入问题有关，不改变梯度期望，但是可以压低方差：

\[
\mathbb{E}_{y\sim\pi_\theta} \left[ b(x)\,\nabla_\theta\log\pi_\theta(y\mid x) \right] = 0
\]

优势 \(A\) 衡量这条回答相对于该问题平均水平的超额收益。

只最大化奖励会出现奖励黑客问题，模型疯狂迎合打分规则，遗忘原有知识。因此 RLHF 加入 KL 正则项，约束策略和冻结的 SFT 参考模型 \(\pi_{\mathrm{ref}}\) 之间的分布偏移：

\[
J(\pi) = \mathbb{E}_{x,y\sim\pi}\big[r(x,y)\big] -\beta\, \mathbb{E}_x D_{\mathrm{KL}} \left( \pi(\cdot\mid x)\,\|\,\pi_{\mathrm{ref}}(\cdot\mid x) \right)
\]

\(\beta\) 控制约束强度，数值越大，模型偏离参考分布的惩罚越重。整条回答的 KL 散度可以拆成逐 token 求和形式：

\[
D_{\mathrm{KL}}(\pi\|\pi_{\mathrm{ref}}) = \mathbb{E}_{y\sim\pi} \sum_t \log \frac{\pi(y_t\mid s_t)} {\pi_{\mathrm{ref}}(y_t\mid s_t)}
\]

训练时，参考模型同步读取采样轨迹，输出每个位置的对数概率，逐 token 计算 KL 惩罚，和任务奖励合并得到回报。

PPO 是 RLHF 最常用的求解算法。长文本采样成本很高，工程上一般先一次性采样一批轨迹，在这批固定数据上多次更新参数，减少反复采样的开销。参数更新之后，这批轨迹就来自旧版本模型，因此我们单独保存采样时的策略快照 \(\pi_{\mathrm{old}}\)，计算新旧策略的概率比：

\[
\rho_t(\theta) = \frac{\pi_\theta(y_t\mid s_t)} {\pi_{\mathrm{old}}(y_t\mid s_t)}
\]

裁剪目标限制单次更新幅度，防止策略剧烈漂移：

\[
J_{\mathrm{clip}} = \mathbb{E}_t \Big[ \min\big( \rho_t A_t,\; \operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t \big) \Big]
\]

\(\epsilon\) 是裁剪阈值。优势为正时，概率比超过 \(1+\epsilon\) 之后，收益不再继续上涨；优势为负时，概率比低于 \(1-\epsilon\) 之后，不再继续压低概率。

> 
> 注意区分两个极易混淆的模型：\(\pi_{\mathrm{old}}\) 是生成这批数据的策略快照，用来计算概率比；\(\pi_{\mathrm{ref}}\) 是固定不变的 SFT 原点，用来做 KL 约束。

为了更稳定地估计长轨迹的优势，常用广义优势估计 GAE：

\[
G_t = \sum_{k=t}^{T}\gamma^{k-t}r_k
\]

\[
\delta_t = r_t+\gamma V(s_{t+1})-V(s_t)
\]

\[
A_t^{\mathrm{GAE}} = \sum_{l=0}^{T-t}(\gamma\lambda)^l\delta_{t+l}
\]

\(\gamma\) 是折扣系数，\(\lambda\) 控制向后看多远。\(\lambda=0\) 时更依赖价值模型，\(\lambda=1\) 时使用更多实际反馈，波动更大。

## 6.4 GRPO

GRPO（Group Relative Policy Optimization）是 RLHF 的重要变体，核心特点是省去了单独训练价值模型的步骤，用组内相对奖励估计优势。

我们先让模型对同一道题生成 \(G\) 份回答，再评价每份回答，得到 \(r_1,\ldots,r_G\)。由于它们面对相同的问题，可以用组内平均奖励代表当前模型在这道题上的表现，再比较每份回答高于或低于平均值多少。一种常见的结果奖励版本写为：

\[
\bar r = \frac{1}{G}\sum_i r_i, \qquad \sigma_r = \sqrt{\frac{1}{G}\sum_i(r_i-\bar r)^2}, \qquad A_i = \frac{r_i-\bar r}{\sigma_r+\varepsilon}
\]

\(\bar r\) 是均值，\(\sigma_r\) 是组内标准差，\(\varepsilon\) 是防止除零的小常数。先减去均值，再用标准差缩放，就得到每条回答相对于同题其他候选的优势。

如果四条回答全对或全错，它们的奖励相同，优势就为零。全对说明这批候选没有表现差异，全错则说明当前采样没有找到成功解法。我们可以记录这种组的占比，再调整题目难度或采样安排。

得到优势后，仍然可以使用 PPO 的新旧概率比。把采样时的版本记为 \(\pi_{\mathrm{old}}\)，当前训练模型记为 \(\pi_\theta\)，则第 \(i\) 条回答在位置 \(t\) 的比值为：

\[
\rho_{i,t} = \frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}{\pi_{\mathrm{old}}(y_{i,t}\mid x,y_{i,<t})}
\]

将 \(A_i\) 放进裁剪目标，并在每条回答内平均，再对组内候选平均，得到基本形式：

\[
J = \mathbb{E}_x \left[ \frac{1}{G}\sum_i \frac{1}{|y_i|}\sum_t \min\left( \rho_{i,t}A_i,\; \operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i \right) \right] -\beta\mathcal{K}
\]

\(|y_i|\) 是回答的有效长度，\(\epsilon\) 是裁剪范围，\(\mathcal{K}\) 是按选定方式计算的参考 KL。它保留了 PPO 的裁剪结构，但用组内比较取得优势，省去了单独训练价值模型的步骤。

### 核心代码

```
import torch

def group_advantage(reward, eps=1e-6):
    mean = reward.mean(-1, keepdim=True)
    std = reward.std(-1, keepdim=True, unbiased=False)
    return ((reward - mean) / (std + eps)).detach()

def clipped_loss(new_logp, old_logp, advantage, action_mask, eps=0.2):
    lengths = action_mask.sum(-1)
    if (lengths == 0).any():
        raise ValueError("轨迹没有有效动作")
    ratio = (new_logp - old_logp.detach()).exp()
    adv = advantage.detach().unsqueeze(-1)
    objective = torch.minimum(
        ratio * adv,
        ratio.clamp(1 - eps, 1 + eps) * adv,
    )
    per_answer = (objective * action_mask).sum(-1) / lengths
    return -per_answer.mean()
```

### 长度与难度

写出裁剪目标之后，还需要决定怎样把不同回答的 token 损失合成一个数。前面的代码先在每条回答内部取平均，再对回答取平均，所以一份两百个 token 的回答与一份两千个 token 的回答，在批次中具有相同的总权重。这样处理时，短回答的每个 token 会取得更大的权重。若我们改为把批次中所有有效 token 放在一起平均，长回答则会因为包含更多位置而占据更大份额。这两种归一化分别对应按回答和按 token 分配训练权重，会产生不同的更新。

为了看清这个区别，暂时省略 KL，把每个位置的裁剪收益记为 \(u_{i,t}\)，回答有效长度记为 \(L_i\)。两种聚合可以写为：

\[
J_{\mathrm{answer}}
=
\frac{1}{G}\sum_{i=1}^{G}
\frac{1}{L_i}\sum_{t=1}^{L_i}u_{i,t},
\qquad
J_{\mathrm{token}}
=
\frac{\sum_{i=1}^{G}\sum_{t=1}^{L_i}u_{i,t}}
{\sum_{i=1}^{G}L_i}
\]

这里分母中的长度都来自本轮已经采好的回答，反向传播时不对这些整数求导。不过，回答长度会与正确性，奖励和生成方式相关，因此长度仍会通过样本权重影响学习。比如，失败轨迹经常包含较长的重复分析，按 token 聚合就会让这些轨迹中的位置占据更多权重。按回答聚合也有自己的偏向，不能仅凭某种写法更简洁就决定使用它。我们需要同时观察正确与错误回答的长度，单个位置的梯度权重，以及更新后的任务表现。

组内标准差也会改变题目之间的权重。假设奖励只有 0 和 1，一组候选的成功比例为 \(p\)，忽略数值稳定项时，标准差为 \(\sqrt{p(1-p)}\)。同样一条正确回答，在成功比例较低的组中，会取得更大的标准化优势；同样一条错误回答，在多数候选已经成功的组中，则会取得更强的负优势。这个缩放使不同题目的学习信号发生了变化，所以它既包含稳定数值尺度的作用，也包含对不同成功率题目的重新加权。

Dr. GRPO 对长度归一化和组内标准差带来的偏差作了分析，并采用固定归一化常数与不除组内标准差的优势构造来调整更新。DAPO 则采用按有效 token 聚合的目标。理解这些方法时，可以先把同一批回答的奖励和概率固定，只改变优势与分母，比较每条回答实际获得多少权重，再观察训练之后长度与正确率怎样变化。算法之间的区别由这些计算具体产生，名称本身没有说明哪一种一定适合当前数据。

### 探索与采样

如果同一道题的候选全部成功或全部失败，减去组内均值后，结果奖励对应的优势都会变成零。此时，基于这一相对奖励的策略项没有提供区分候选的信号，KL 或额外的熵项仍然可能产生梯度。随着训练推进，简单题可能越来越多地出现全对，过难题则长期全错。即使每批采样的题目数量保持不变，真正提供相对学习信号的题目也可能持续减少。

DAPO 的动态采样会过滤奖励全同的候选组，并继续采样，以维持一批中有效题目的数量。这样能够减少训练端处理零优势组的开销，但前面已经消耗的生成仍然需要计入成本。我们应同时保存原始采样题目数，留下的候选组数，以及被过滤组的成功比例。保留下来的组已经经过选择，仅看它们的平均奖励，就会失去对原始题目分布的认识。

过滤也需要与课程安排配合。长期全错的题目可能超出当前模型能力，或者检查器与题意存在冲突；全对的题目则可能适合降低采样频率。我们可以先检查数据和奖励，再根据难度分层安排采样。如果一批中有效组越来越难凑齐，持续生成更多候选会显著增加开销，这时应重新检查题目组成，组大小与过滤规则，而不能只维持一个看起来不变的训练 batch。

探索还受到裁剪范围影响。正优势候选需要提高其生成概率，但概率比超过上界之后，裁剪目标便不再奖励继续提高。DAPO 的 Clip-Higher 分别设置上下界，通过放宽上界，为部分低概率而获得正奖励的选择保留更大的提升空间。放宽以后仍然需要观察概率比的尾部，裁剪比例和任务表现，因为某些候选可能因偶然奖励而获得过强更新。

输出长度上限也会影响反馈。模型已经生成很长的推理，却在给出最终答案之前被截断，如果评分器直接将其与完整错误答案同样记零，就会混合两种不同失败。DAPO 对过长输出加入了相应的奖励处理，用来减少这种噪声。实际训练中，应分别记录正常结束，达到长度上限和解析失败，再按照预先规定的方式评分。结束符需要进入有效动作统计，padding 则应排除，否则损失中的长度与模型真正生成的长度就会不一致。

### 概率比与更新

GRPO 的概率比在每个 token 上计算。同一条回答中，有些位置可能变化很小，少数位置却出现很大的比值。即使整条回答的奖励只有一个数，这些位置也会分别触发裁剪，因而形成不同的更新强度。长回答包含更多位置，出现极端比值的机会也更多。我们可以把每个位置的 log 概率差保存下来，检查极端变化集中在哪些 token，而不能只看整条回答的平均损失。

GSPO 把一条回答的 log 概率差先按长度取平均，再取指数，得到用于序列级裁剪的比值：

\[
s_i(\theta)
=
\exp\left[
\frac{1}{L_i}
\sum_{t=1}^{L_i}
\left(
\log\pi_\theta(y_{i,t}\mid h_{i,t})
-
\log\pi_{\mathrm{old}}(y_{i,t}\mid h_{i,t})
\right)
\right]
\]

这里 \(h_{i,t}\) 是第 \(i\) 条回答在位置 \(t\) 之前的上下文。这个量等于整条回答似然比的 \(L_i\) 次方根，在数值上相当于对逐 token 比值取几何平均。随后用同一个 \(s_i\) 与该回答的组内优势构造裁剪收益，整条回答共享这一裁剪判断。

这种归一化能够减少少数极端 token 对裁剪数值的直接影响，也是 GSPO 用来改善长序列训练稳定性的一个设计。它同时改变了优化目标：长度归一化之后的比值，不能当作原始轨迹概率的完整重要性权重。我们需要结合它的目标与梯度解释训练效果，不能把“采用了概率比”直接理解为获得了无偏的分布校正。

原始 GSPO 的序列级优势也不要求每个位置都具有相同价值。如果一条回答靠后出现关键错误，结果奖励仍然只告诉我们整条回答是否成功，序列级裁剪没有额外识别出出错步骤。因此，裁剪粒度与信用分配需要分别考虑。前者约束一次更新怎样使用概率变化，后者决定奖励怎样影响不同动作。

Soft Adaptive Policy Optimization，简称 SAPO，还尝试用平滑权重调整代替硬裁剪，让概率偏移较大位置的权重逐渐变化。比较这些方法时，可以固定初始模型，数据，奖励和生成预算，再观察更新幅度，候选多样性与独立任务成绩。若同时更换奖励器和采样设置，分数提高以后就难以说明收益来自哪一部分。

### 采样与训练

实际训练中，采样端与训练端未必读取同一版本的参数。生成一批长回答期间，训练端可能已经更新了几步；同一批轨迹又可能被重复使用。即使双方使用相同权重，不同精度，算子与推理实现，也可能使同一个 token 的条件概率出现差异。为了判断样本怎样参与更新，我们需要把真正生成它的分布与训练端计算的分布分别记录。

记实际采样分布为 \(\mu\)，训练端选定的旧策略为 \(\pi_{\mathrm{old}}\)，当前策略为 \(\pi_\theta\)。在同一个已观察前缀上，概率比可以分成：

\[
\frac{\pi_\theta(a_t\mid h_t)}{\mu(a_t\mid h_t)}
=
\underbrace{
\frac{\pi_\theta(a_t\mid h_t)}
{\pi_{\mathrm{old}}(a_t\mid h_t)}
}_{\text{本轮策略更新}}
\underbrace{
\frac{\pi_{\mathrm{old}}(a_t\mid h_t)}
{\mu(a_t\mid h_t)}
}_{\text{采样分布差异}}
\]

第一项对应前面裁剪目标中的新旧策略变化，第二项则反映实际采样与训练旧策略之间的差异。如果我们用训练端重新计算的概率替代采样概率，却没有保存这项差异，就可能在不知情的情况下改变更新权重。轨迹因此应保留采样模型版本，采样时的 log 概率，生成参数和有效动作位置，训练端再在相同前缀上计算所需概率。

这个逐位置等式没有完整校正历史前缀的分布。对于能够重放并满足支持条件的整条轨迹，严格的重要性比涉及此前动作概率的乘积，轨迹越长，权重方差往往越难控制。工程上可以采用截断权重，按序列聚合或拒绝异常样本等近似，但这些做法会改变偏差与方差。verl 的 Rollout Correction 将重要性加权与样本拒绝分别实现，便于区分保留样本后的权重调整，以及哪些样本根本不进入更新。

采样温度和 top-p 也属于实际分布的一部分。只保存未经采样变换的模型概率，未必等于 \(\mu\)；如果 top-p 已经排除了某些动作，后续加权也无法从这批样本中恢复没有机会出现的动作。采用什么概率作分母，是否对变换作近似，都需要与所选训练目标一致。实践中可以先限制每批更新次数和最大策略滞后，再根据偏移指标决定加权，等待新样本或丢弃旧样本。

一套基本检查应把平均奖励，独立正确率，回答长度，截断比例，零优势组比例，概率比和采样版本差放在一起看。如果奖励上升而正确率没有改善，应检查奖励定义；如果长度突然上涨，应分开看成功与失败轨迹，并核对归一化；如果概率比出现很长的尾部，则要检查学习率，重复更新次数和采样新鲜程度。生成熵能够帮助观察分布是否收缩，但不同位置和不同任务的熵含义不同，还需要结合实际候选与结果判断。

这些检查适合从小规模同步训练开始建立。先确认损失掩码，结束符，奖励和概率计算对应同一批动作，再逐步增加回答长度，组大小和异步程度。每增加一项复杂性，都保留相同条件下的基线，才能判断提高吞吐或延长推理之后，模型是否仍在学习预期的行为。

## 6.5 DPO 直接偏好优化

RLHF 流水线复杂，需要独立奖励模型，在线采样，价值模型，精细调参。DPO 从带 KL 约束的 RLHF 最优条件出发做数学变换，直接在偏好对上训练，不再显式训练奖励模型。

在固定参考模型下，带 KL 正则的最优策略满足：

\[
\pi^*(y\mid x) = \frac{ \pi_{\mathrm{ref}}(y\mid x) \exp\big(r(x,y)/\beta\big) }{Z(x)}
\]

\(Z(x)\) 是归一化常数。这个式子说明：最优策略就是在参考模型基础上，给高奖励回答更高的相对权重。把公式变形，用策略比值反推奖励：

\[
r(x,y) = \beta\log \frac{\pi^*(y\mid x)} {\pi_{\mathrm{ref}}(y\mid x)} +\beta\log Z(x)
\]

代入 Bradley–Terry 偏好模型，同一个问题的归一化项会抵消，得到 DPO 的打分 margin：

\[
m_\theta = \beta \left[ \log\frac{\pi_\theta(y_w\mid x)} {\pi_{\mathrm{ref}}(y_w\mid x)} - \log\frac{\pi_\theta(y_l\mid x)} {\pi_{\mathrm{ref}}(y_l\mid x)} \right]
\]

对标注事件取负对数似然，得到 DPO 损失：

\[
\mathcal{L}_{\mathrm{DPO}} = -\mathbb{E}_{(x,y_w,y_l)\sim D} \log\sigma(m_\theta)
\]

对应的梯度：

\[
\nabla_\theta\mathcal{L} = -\beta\,\sigma(-m_\theta) \left[ \nabla_\theta\log\pi_\theta(y_w\mid x) - \nabla_\theta\log\pi_\theta(y_l\mid x) \right]
\]

模型会提高胜出回答的相对概率，压低落败回答的相对概率。当模型还分不清两份回答优劣，梯度权重很大；当模型已经充分区分两者，梯度会自然衰减。这里有一个容易踩坑的点：优化目标是相对概率差，胜出回答的绝对概率不一定上升，有可能两份回答概率一起下降，只是落败的那一份下降更多。

\(\beta\) 是 DPO 的核心超参，和 RLHF 里的 KL 惩罚系数含义对应，控制策略偏离参考模型的强度。DPO 属于离线算法，不需要在线采样，工程实现简单很多。

### DPO 家族变体

- SimPO：去掉参考模型前向，用单条回答平均 log 概率做对比，额外设置目标分差 \(\gamma\)，降低计算成本；
- ORPO：把 SFT 损失和偏好损失融合到同一个目标，一边学习复刻胜出回答，一边学习相对优劣，不需要参考模型；
- KTO：适配非成对的单点反馈，样本只有单条回答和好坏标签，不需要为同一个问题补齐一对候选。

### 训练实现要点

DPO 训练的基础计算，是算出整条回答的对数概率。模型前向输出 logits，维度为 \([B,T,V]\)，经过 log-softmax，取出对应 token 概率，只对回答部分求和，prompt，padding 位置用标签 -100 屏蔽。

```
import torch
import torch.nn.functional as F

def response_logp(logits, labels):
    target = labels[:, 1:]
    valid = target.ne(-100)
    safe_target = target.masked_fill(~valid, 0)
    logp = F.log_softmax(logits[:, :-1].float(), dim=-1)
    selected = logp.gather(-1, safe_target.unsqueeze(-1)).squeeze(-1)
    if (valid.sum(-1) == 0).any():
        raise ValueError("回答中没有有效标签")
    return (selected * valid).sum(-1)

def dpo_loss(policy_w, policy_l, ref_w, ref_l, beta):
    margin = beta * (
        policy_w - ref_w.detach() - policy_l + ref_l.detach()
    )
    return -F.logsigmoid(margin).mean()
```

参考模型全程冻结。工程上常把 chosen 和 rejected 拼成 \(2B\) 批次一起前向。模板，分词器，结束符，截断规则，策略模型和参考模型必须完全一致。

## 6.6 对齐失效模式与治理
偏好对齐本质是用代理目标逼近人类偏好，只要代理和真实偏好存在间隙，就会出现失效。这些问题不是 DPO 独有的，只是不同范式暴露短板的方式不一样。

### 6.6.1 奖励黑客 Reward Hacking
模型学会迎合打分规则，产出代理目标下的高分结果，但内容并不符合人的判断标准。
RLHF 有显式奖励模型，黑客更容易直接爆发。模型会用无意义扩写，套路化话术，刻意对齐评分格式等方式拿到高分，当输入脱离奖励模型见过的分布，欺骗的空间会进一步变大。DPO 没有独立奖励模型，但它的偏好对比目标同样是代理信号，持续在有限偏好对上训练，模型也会走向圆滑保守的输出，牺牲事实和推理能力换取对比胜率。

KL 约束是通用的第一道防线，它限制模型偏离 SFT 基准的幅度，压缩投机空间。RLHF 可以组合多个奖励信号，引入程序验证这类可自动核验的反馈，降低单一奖励模型的漏洞。DPO 需要持续扩充偏好对的多样性，避免模型记住局部的胜负模式。训练过程中不能只看损失和偏好准确率，必须对照人工评估，一旦代理分数和人的判断脱节，就要停止迭代。

### 6.6.2 模式坍缩 Mode Collapse
模型的生成空间不断收缩，面对不同输入，倾向复用少数安全稳妥的回答模板，多样性持续衰减。
RLHF 里，只要一组模板稳定拿到正向奖励，PPO 就会不断抬高它的概率，慢慢放弃其他同样正确但收益不稳定的解法。DPO 的坍缩大多来自数据本身，如果偏好集里胜出样本高度趋同，模型会直接收敛到这类保守答案。

多样性指标要纳入训练监控，生成熵，distinct-n 出现明显下滑时及时早停。偏好数据需要主动加入风格，长度，解法路径的变化，不能只收集一类标准答案。少量 SFT 损失可以保留基座原本的生成分布，配合 KL 约束一起防止模型被偏好信号锁死。

### 6.6.3 迭代对齐坍缩
这是在线 RLHF 闭环迭代特有的风险，DPO 离线训练不存在这个循环。
策略生成样本，标注后用来更新奖励模型，新的奖励模型再去优化策略。几轮循环之后，模型会专门生成欺骗奖励模型的内容，这些样本流入奖励模型的训练集，一步步把奖励模型的判断带偏，整体对齐水平持续下滑。

每一轮更新奖励模型时，都保留一部分原始离线人工标注作为锚点，不让新样本完全接管奖励模型的判断。严格控制每一轮策略更新允许的 KL 偏移，不让模型分布跳变得太快。评估不能依赖奖励模型，需要独立的人工验证集，同时尽量控制闭环迭代次数，不做无限循环。

### 6.6.4 奖励模型自身失效
这个问题只属于 RLHF 体系，DPO 不依赖独立奖励模型，不会遇到这类故障。
一类是奖励坍缩，训练后期奖励模型对好坏回答打出的分数差距不断缩小，区分能力退化，无法给策略提供有效梯度。另一类是学习到数据里的虚假关联，比如把长文本，特定语气当成高分信号，而不是判断回答本身的正确性。

解决手段
奖励模型以验证集两两对比准确率为核心指标，在峰值附近早停，不要一直训练。构造对照样本，让正负样本在长度，句式上接近，只保留回答质量本身的差异，破除伪相关。对奖励做标准化缩放，稳定不同版本奖励模型的尺度，也可以增加事实校验，指令遵从的辅助监督，引导奖励模型关注核心质量。
