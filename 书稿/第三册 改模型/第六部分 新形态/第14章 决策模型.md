# 第 14 章 决策模型

## 14.1 输出

生成模型的输出是 token 序列。软件要拿它做路由，质检或是否放行，还要把字符串解析成字段。决策模型的输出就是字段和概率。

TypeSafe 把这类模型称为 System One。Jev 是其中的公开模型：输入一段 state，对若干结构化问题给出判定，不生成回复正文。System One 在这里是模型接口的名字。高频，题型固定的判定从开放文本生成里拆出来，由这种接口来做。

## 14.2 原语

请求包含 state 和一组命名问题。state 是字符串，JSON 对象或数组，例如对话，工单，当前程序状态。同一份 state 上的问题一起算。

Jev 公开的三种问题：

Choice 在给定选项里选一个，返回被选中的项和每一项的概率。Score 把 state 放上有序的档位，返回各档概率和期望分数。Noul 问一件事是否成立，返回成立的概率。

选项集合由调用方给定。模型不能写出集合之外的字符串。它仍然可以选错项，或给出偏离频率的概率。

## 14.3 校准

校准指：在所有给出概率约 \(p\) 的判定里，事件实际发生的比例接近 \(p\)。这是一批预测上的性质。单次 0.9 仍可能是错的。阈值策略用的就是这个性质：低于阈值就转人工。

生成模型若被要求在文本里写一个置信度，这个数常常偏高，而且换一种问法就变。决策模型把概率对准频率写进训练目标。厂商给出的概率仍要在自己的数据上核对落点。二分类概率的排序可以是好的，相对固定的 0.5 阈值却可能偏。阈值用训练数据标定之后再看 F1。

## 14.4 RLCD

TypeSafe 将训练方法称为 RLCD，Reinforcement Learning for Calibrated Decisions。更新对象是类型化判定。目标包含判得对不对，以及概率是否对准经验频率。

第 5 章的策略梯度更新的是 token 序列。奖励来自偏好模型，或来自数学和代码的验证器。消费 RLCD 的程序直接读字段。消费 token 策略的程序先解析文本。

## 14.5 接入

工单 state 用 Choice 选处理队列。工具参数用 Noul 决定是否允许执行。生成模型写出的草稿用 Score 或 Noul 看是否接地，是否含有不该出现的个人信息。大批日志用同一组问题打成字段，而不是逐条生成说明文字。

延迟落在一次前向的量级，才能放进同步请求。接口里没有开放解码，也就没有按输出 token 计的那一部分费用。具体数字以当时的部署为准。

写邮件，写代码，多步工具循环，仍用生成模型。决策模型放在循环的路由和放行上。第 5 章的一部分打分可以换成这种判定，概率要在本任务的分布上重新看校准曲线，见第 12 章。准确率只报 argmax 时，校准坏了看不出来。

选项顺序旋转之后准确率应保持。准确率随选项顺序变，学到的是位置。拿掉问题只留 state，准确率掉到随机，才说明预测用到了问题本身。细粒度噪声标签，低资源语言，开放的质量量表，仍然容易差。输入以文本和 JSON 为主时，图像和音频要另接模型。
