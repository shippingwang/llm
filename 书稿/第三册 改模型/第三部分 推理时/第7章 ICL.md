# 第 7 章 ICL

## 7.1 条件

ICL 不更新 \(\theta\)。当次上下文 \(c\) 里放说明和示范，输出从

\[
y\sim p_\theta(y\mid c)
\]

里采样。\(c\) 变了，条件分布变了。没有新的 checkpoint。每次请求都要为这些 token 付 Prefill。

指令模型里，这些 token 把已经存在的行为约束到当前任务的格式和边界上。基座里没有的计算，不会因为多放几条例子就出现。

## 7.2 示范

一条正例，一条容易混的反例，一条信息不够时该拒绝或该追问的例子，比十条表面不同的正例更有用。例子定义的是标签和输出形状。

按当前输入去检索示范时，检索的是决策结构相近的例子。词面重叠高，决策不一样，检索到了也是错条件。

示范，检索片段和历史对话占同一个窗口。硬约束放在稳定的高优先级消息里。当前问题和输出格式靠近生成开始的位置。窗口能装下很长的上下文，不表示每一段被同样使用。

## 7.3 权限

system 消息写目标和约束。user 消息是这次的任务。检索到的文档和工具返回是待处理的数据。把文档和 system 拼进同一段纯文本，模型分不清要执行的句子和要分析的句子。文档里的指令就会被执行，这就是 prompt injection。

要求输出 JSON，到 constrained decoding，再到工具调用，约束的都是下一个 token 的允许集合。语法合法之后，数值范围，对象归属和权限仍由调用方检查。

规则还在变，或每个租户一份，放在上下文里。规则已经固定，每次请求都重复占同一段 token，再写进 SFT。相对偏好和需要自己探索的解法，分别见第 4 章和第 5 章。
