# 第 7 章 上下文学习 ICL

前一章介绍的 TTT 是推理阶段唯一会临时改动权重的技术，而本章的 ICL（In-Context Learning，上下文学习）与下一章的 RAG，走的是完全无参数更新的轻量路线：仅通过调整输入 Prompt 的内容，就可以引导模型输出符合预期的结果，成本最低，落地最快，是业务快速迭代的首选方案。

### 7.1 ICL 到底是什么

ICL 的核心逻辑是：**模型不需要更新任何参数，只需要在输入中给出几个示例，就能学会执行对应的任务**。它利用了大模型在预训练阶段学到的模式识别与续写能力 —— 模型看到输入里的若干组输入 - 输出范例，会自动识别其中的任务范式，并按照同样的格式与逻辑处理最后一个待求解的输入。

按照示例数量，ICL 分为三类：

- **零样本（Zero-shot）**：不给任何示例，只给指令，直接让模型输出结果。对基座的指令跟随能力要求最高，是最常用的日常交互方式。
- **少样本（Few-shot）**：在指令后追加 2~5 个完整的输入输出示例，再给出待求解问题。这是 ICL 的标准形态，适合格式要求严格，规则明确的任务。
- **单样本（One-shot）**：只给一个示例，效果与成本介于零样本和少样本之间。

举一个行程助手场景的少样本 ICL 示例：

```
你是专业行程规划助手，按照天数+核心景点+注意事项的格式输出。
输入：五一去杭州3天
输出：Day1：西湖环湖，景点包含断桥，苏堤，雷峰塔；注意防晒，提前预约景区
输入：元旦去哈尔滨2天
输出：Day1：中央大街，索菲亚教堂，傍晚去冰雪大世界；注意保暖，备好防风装备
输入：国庆去成都3天
输出：
```

模型看到前两组范例，会自动识别任务规则，并按照相同结构输出成都的行程方案，全程不改动任何权重。

### 7.2 ICL 为什么能生效

ICL 是大模型涌现出的核心能力之一，其底层机制至今没有完全统一的定论，但工业界普遍认可两个核心视角：

1. **模式匹配视角**：预训练阶段模型见过海量的文本范式，包括问答，摘要，翻译，分类等各类任务结构。当输入中出现连续的同范式示例时，模型会激活对应任务的表征，将后续输入纳入同一范式进行续写。
2. **隐式微调视角**：少样本示例相当于在推理阶段给模型提供了临时的任务约束，在注意力层面形成了定向的激活偏置，类似于一次虚拟的微调，但这个过程只发生在前向传播中，不会永久改变权重。

这也解释了为什么 ICL 的效果高度依赖基座模型的规模与预训练质量：模型越大，预训练数据越丰富，能识别的任务范式就越多，ICL 的表现就越稳定。

### 7.3 影响 ICL 效果的核心因素

ICL 不是随便丢几个示例就能达到最优效果，其效果对 Prompt 设计非常敏感，核心影响因素有三个：

1. **示例质量**：示例的标注准确性，格式一致性，难度分布，直接决定了模型对任务规则的识别精度。示例自身有错误，格式不统一，会显著拉低最终效果。
2. **示例数量**：通常 0~5 个示例时，效果随数量上升快速提升；超过 8 个之后，边际收益迅速递减。过多示例还会占用上下文窗口，挤压实际输入的空间。
3. **示例排序**：多个示例的排列顺序会影响最终输出，越靠近最终提问的示例，对模型的影响越强。行业常用的优化方式是把难度最高，最贴合目标场景的示例放在最后。

除此之外，示例的多样性，指令的清晰程度，输出格式的明确性，都会对效果产生影响。也正因为如此，Prompt Engineering 才成为独立的工程方向。

### 7.4 与其他技术的边界

- **与 SFT 的区别**：SFT 是把任务规则固化进权重，一次训练永久生效，适合高频稳定任务；ICL 是临时通过示例引导，零成本快速切换任务，适合低频多变，快速验证的场景。
- **与 CoT 的关系**：提示式思维链本质上就是 ICL 的一个子类 —— 示例中不仅包含答案，还包含推理步骤，引导模型分步输出。
- **与 TTT 的区别**：ICL 完全不动权重，仅靠输入引导；TTT 会做临时梯度更新，二者都用于推理时适配，但实现路径完全不同。

### 7.5 现状与局限

ICL 是目前工业界应用最广的推理侧优化技术，几乎所有大模型业务都会用到。它的优势是零训练成本，切换灵活，上线速度快；但短板也非常明确：

1. **上下文占用**：示例需要常驻输入，长上下文场景下会挤占有效输入空间，且增加推理成本；
2. **效果上限有限**：对于高度专业化，强领域知识的任务，仅靠少量示例很难达到微调的效果；
3. **稳定性不足**：对示例顺序，表述方式敏感，同一任务换一种写法效果可能波动较大，难以做严格的质量管控。

行业的共识是：快速验证，低频任务优先用 ICL；任务稳定，流量上来之后，再把验证好的规则通过 SFT 固化到权重里，实现效果与成本的平衡。
