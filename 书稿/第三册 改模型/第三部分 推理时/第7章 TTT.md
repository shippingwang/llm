# 第 7 章 TTT

上下文学习把新材料交给模型，依靠固定参数解释这些材料。另一种思路是在预测之前或预测过程中，利用当前可获得的数据做少量参数更新，使模型适应本次任务。测试时训练，Test-Time Training，TTT，讨论的就是这类方法。

“测试时”说明更新发生的时间，尚未确定更新对象。它可能是一个聊天模型的临时适配器，也可能是序列层中随输入更新的小学习器，还可能是根据测试问题的候选结果更新策略。它们都包含学习步骤，却有不同的数据，目标和状态生命周期。本章分别展开这些路线，说明每一步更新从哪里获得监督，以及更新后怎样继续推理。

## 7.1 适配目标

离线监督训练通常已有答案，真实请求却往往只有输入。要在测试时训练，首先要找到无需知道目标答案就能计算的损失。文本本身可以构成下一 token 预测任务，图像可以构成与训练设计相配合的自监督任务，代码候选则可以根据可执行反馈获得奖励。

设可用材料为 \(d\)，允许更新的参数为 \(\psi\)，一次适配可以写为

\[
\psi_{k+1}
=
\psi_k-\eta\nabla_\psi
\mathcal{L}_{\mathrm{adapt}}(d;\theta,\psi_k)
\]

\(\theta\) 为冻结的主体参数，\(\eta\) 为学习率。适配完成后，用 \((\theta,\psi_K)\) 回答当前问题。如果采用全参数更新，可以把相应参数全部归入 \(\psi\)。这个式子只说明怎样下降适配损失，尚未保证最终任务改善。

两者之间的关系是 TTT 的关键。文档续写更准确，可能帮助模型适应术语和表达，也可能只使它记住常见句式；图像重构损失下降，也不一定提高识别能力。训练阶段若专门让模型学会“怎样从这种自监督更新中获益”，测试时适配通常具有更明确的依据。

可以把这种目标写成内外两层：

\[
\psi'(d)
=
\psi_0-\eta\nabla_\psi
\mathcal{L}_{\mathrm{adapt}}(d;\psi_0),
\qquad
\min_{\psi_0}
\mathbb{E}\,
\mathcal{L}_{\mathrm{task}}(q,a;\psi'(d))
\]

内层利用允许的材料更新，外层检查更新后是否更容易完成任务。训练时可以使用答案 \(a\) 评价外层损失，测试时只执行已经确定的适配程序。若精确穿过内层梯度求导，还会涉及二阶信息，工程中也可能使用近似。它与随意选择一个代理损失临时微调，有不同的训练基础。

适配材料需要界定清楚。只使用当前文档，使用整个测试批次，以及持续使用之前的请求，分别提供不同信息。任务答案不能悄悄进入适配数据；学习率，步数和停止条件也应在开发任务上选择。否则，测试时训练容易变成对测试答案反复调参。

## 7.2 文档适配

对已有因果语言模型，比较直接的做法是在当前文档上继续语言建模。文档 token 为 \(d_1,\ldots,d_n\)，取合适窗口并计算

\[
\mathcal{L}_{\mathrm{adapt}}
=
-\sum_t m_t
\log p_{\theta,\psi}(d_t\mid d_{<t})
\]

掩码排除 padding，以及不希望重复监督的重叠部分。窗口前部可以保留上下文，后部只对新出现的 token 计损失，使相邻片段保有一定连续性。训练窗口大小，重叠和遍历次数共同决定模型实际学习了哪些内容。

这里使用的是因果续写目标。一个没有掩码预训练基础的 decoder，不能仅把输入中的若干词换成 MASK，就自然完成双向重构。位置可见性，输入格式和训练目标需要配套。对长文档，也不能因为最终只更新少量参数，就忽略长序列反向传播的成本。

一种便于隔离的实现是为每份文档创建临时 LoRA。主体权重冻结，适配器从同一初始值开始，读入允许的窗口，执行固定步数，再用更新后的模型回答问题。请求结束后丢弃适配器与优化器状态；若后续多个问题共享同一文档，也可以按会话协议复用。

仅训练 LoRA 会减少可训练梯度和优化器状态，却仍需要通过主干计算把梯度传到适配器。每个训练窗口依然包含前向，反向和激活保存，不能按 LoRA 参数占比直接估计总加速。适配若使用很长材料，激活，重算和数据读取可能成为主要开销。

更新范围与学习率也会影响遗忘。反复拟合同一文档，可能使模型过度偏向其中的表达，削弱原本的指令遵循。可以限制步数，使用较小学习率，或加入偏离起点的惩罚：

\[
\mathcal{L}
=
\mathcal{L}_{\mathrm{adapt}}
+\lambda\|\psi-\psi_0\|_2^2
\]

这个正则约束更新幅度，但不能判断文档是否真实。材料中的错误，偏见和恶意内容仍可能进入适配过程，因此数据来源与任务目标都需要检查。

完成适配后，应释放训练图，再建立生成所需的新缓存。旧 KV 使用旧权重计算，只要更新影响相关层表示，就可能已经失效。继续使用原缓存会混合两套参数下的状态，尤其在长序列或多轮问答中难以解释。即使只更新少量适配器，也要依据其所在层重新判断缓存有效范围。

产出也应说明清楚。一次文档适配通常得到的是临时参数增量与当前回答，并没有自动形成可供所有任务使用的新通用模型。若要把增量长期保存，需要固定文档，基座，模板，训练配置和有效范围，并重新检查其他任务上的影响。

## 7.3 快速权重

另一类 TTT 直接改变序列层的状态定义。第一册中的循环模型维护一个随 token 更新的状态，线性注意力可以用固定大小矩阵累计信息。TTT 层则把一个小学习器的参数作为状态，每读入新内容，就通过自监督梯度更新这个学习器。

以线性学习器 \(f_W(k)=Wk\) 为例，输入表示投影成 \(k_t,v_t,q_t\)。用 key 预测 value，定义

\[
\ell_t(W)
=
\frac12\|Wk_t-v_t\|_2^2
\]

设 \(k_t\in\mathbb{R}^{d_k}\)，\(v_t\in\mathbb{R}^{d_v}\)，则 \(W\in\mathbb{R}^{d_v\times d_k}\)，梯度为

\[
\nabla_W\ell_t
=
(Wk_t-v_t)k_t^\top
\]

一步更新得到

\[
W_t
=
W_{t-1}
+\eta_t(v_t-W_{t-1}k_t)k_t^\top
\]

它先读取旧状态对当前 key 的预测，再将预测误差写回矩阵。与单纯累加 \(v_tk_t^\top\) 相比，写入量依赖已经记住多少信息，因此具有纠正已有映射的含义。随后可以通过 \(o_t=W_tq_t\) 查询状态。

更新前还是更新后读出，应遵循具体层定义。如果 key，value 和 query 都来自当前位置已可见的输入，更新后读出仍可以用于预测下一个 token，保持因果性。若训练时把尚不可见的目标直接用于状态更新，再在同一位置评价，就会发生信息泄漏。分析这类层时，应把输入位置，更新目标和预测位置逐项对齐。

可以用一维情形检查更新的含义。设 \(k_t=1\)，目标 \(v_t=2\)，初始权重为 0，学习率为 0.25。第一次预测为 0，误差为 2，权重更新到 0.5；再用同一个训练对更新，误差变为 1.5，权重更新到 0.875。预测逐渐靠近目标，每次写入量随剩余误差减小。若此后又把同一个 key 对应到另一个 value，新的更新就会改写已有映射。这说明快权重既能学习关联，也会在输入冲突时发生干扰。

多维状态用外积把误差沿 key 的方向写入。相近 key 会影响相近的映射方向，正交 key 则更容易被区分；实际模型还会通过共享投影学习什么信息值得分开表示。学习率决定当前信息写入多强，状态结构决定可以同时保存多少关联，外层训练再让这些选择服务于语言建模。这样，内层公式才与最终序列任务联系起来。

快权重 \(W_t\) 是本序列的动态状态，投影矩阵，初始值和学习率生成器则可以是离线训练的共享参数。离线语言建模损失通过整个状态演化更新共享参数，让内层学习器逐渐学会保存有利于下一词预测的信息。推理时，主要继续更新当前序列的快权重，主体共享参数可以保持固定。

TTT-Linear 和 TTT-MLP 分别使用线性模型与小型多层感知机作为学习器。原始研究在 125M 到 1.3B 等规模上比较了它们与其他序列模型。MLP 提供更丰富的状态表达，同时增加内层计算与内存访问；一种结构在语言建模上有效，也不代表可以直接替换任意已训练模型的注意力层。

逐 token 的公式便于理解，直接执行却容易形成低效循环。GPU 更适合处理较大矩阵，因此实际实现会使用分块，小批量内层更新和相应代数重排。一个块内多个训练对若在同一旧权重上计算梯度，再一起更新，所得过程与严格逐 token 更新也可能不同，需要与训练设计保持一致。

固定大小快权重使状态存储不必随历史长度线性增长，但状态容量依然有限。它可以压缩统计规律和关联，却未必保留远处每个细节。精确字符串检索，多个相近事实区分，以及长期状态干扰，都需要单独检查。历史越长，更新之间相互覆盖的问题越值得关注。

## 7.4 测试时强化学习

测试问题没有标准答案，却允许生成多条候选时，还可以从候选之间的关系估计反馈。TTRL 研究了利用多数投票形成伪奖励，再执行策略更新的路线。它从无标签测试问题出发，仍然需要回答提取，候选采样和明确的优化目标。

对于答案可归一化的任务，先采样 \(G\) 条解答，抽取多数答案 \(\hat a\)，再为与 \(\hat a\) 一致的候选给较高奖励。随后可以按第 4 章的组内优势和裁剪目标更新策略。训练不读取真实答案，但使用了当前测试问题以及模型已有的答案分布。

多数答案可能正确，也可能代表共同错误。若模型最初已经能产生多种有效解法，投票可能提高监督质量；若所有候选都漏掉同一条件，更新会强化这个遗漏。候选多样性，题目分布和答案归一化因此共同决定伪奖励的可靠程度。

参数更新还可能影响之后的采样。第一次投票偏向某答案，更新后该答案更容易出现，下一轮投票又更支持它，这会形成自我强化。单看组内一致性提升，无法说明推理已经改善。需要保留独立开发任务，不同种子和固定预算下的结果，检查收益是否来自更好的泛化。

对于代码或交互环境，可执行反馈可能提供比投票更直接的信号。即便如此，测试时允许执行哪些测试，是否共享任务状态，失败是否重置，都应提前定义。利用隐藏答案选择候选，与在允许环境中执行程序，是不同的信息条件。

TTRL 的产出是经过测试时更新的策略状态，需要按协议决定是每题丢弃，同批共享还是持续保留。它与只生成多个候选再投票相比，多出了训练前向反向，参数状态和缓存失效成本。比较两者时，应把这些额外计算一并计入。

## 7.5 实践与部署

文档适配，TTT 层和测试时强化学习，都需要管理两类状态：模型长期共享的参数，以及当前任务产生的更新。前者可以由很多请求共同读取，后者通常需要隔离。两个用户同时修改同一份临时适配器，会相互污染结果；一个请求恢复参数，也可能覆盖另一个请求刚完成的更新。

请求结束后恢复初始状态，常称为 episodic 适配；把更新延续到后续数据，则属于 continual 设置。持续适配可能利用稳定的数据流，也会累积错误与遗忘。评测中的问题顺序，重置频率和跨题共享范围，由此成为方法条件，不能省略。

在部署前，可以先估算一次请求的总耗时：

\[
T_{\mathrm{request}}
=
T_{\mathrm{prepare}}
+K\,T_{\mathrm{update}}
+T_{\mathrm{rebuild}}
+T_{\mathrm{generate}}
\]

这里更新耗时要在实际窗口，批量和参数范围上测量，重建还可能包括重新计算缓存。对于只问一次的文档，适配成本未必能收回；同一文档后续有许多问题时，则可以研究把一次适配成本分摊到多个请求。回答质量仍需与直接长上下文和检索基线比较。

2025 年末的 TTT-E2E 进一步把长上下文建模写成持续学习过程。它使用滑动窗口 Transformer，通过读取上下文时的下一词训练把部分历史信息写入权重，并在离线阶段学习适合这种更新的初始化。报告包含在 164B token 上训练的 3B 模型，并在指定 128K 上下文实验中获得相对全注意力约 2.7 倍的速度提升。这些数字对应其架构，实现与硬件条件，不能直接作为任意聊天模型临时适配的预期。

这种发展把问题从“测试时多训几步是否有用”，推进到“怎样训练一个善于在线学习的模型”。它也说明，架构设计与适配算法可能共同决定效果。固定窗口限制历史注意力访问，权重更新承担部分长程信息保存，两者需要联合训练与验证。

实际使用时，应先建立不更新参数的可靠方案。若材料能够被检索准确找到，直接提供原文通常更容易核对；若任务规律复杂，输入持续变化，才更有必要研究适配收益。最终报告需要同时说明使用了哪些材料，更新了哪些状态，付出多少计算，以及在独立任务上保留了多少能力。这样才能判断额外训练是否真正改善了当前系统。
