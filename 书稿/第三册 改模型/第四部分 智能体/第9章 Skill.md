## Skill

Skill 是智能体的原子执行单元，负责将具体功能封装成大模型可识别，可调用的标准化模块，是连接模型语言能力与真实世界执行能力的桥梁。

### 9.1 核心定义

每一个 Skill 对应一项独立的可执行能力，接收结构化输入，返回结构化输出。常见的 Skill 包括搜索引擎，数值计算，代码执行，数据库查询，文件读写，第三方 API 调用等。
大模型负责决策是否调用技能，生成调用参数；Skill 负责实际执行并返回结果，二者配合完成纯文本模型无法实现的落地操作。

### 9.2 标准 Skill 三要素

一个可被模型稳定调用的 Skill，必须包含三个标准化组成部分：

1. **功能描述**：用自然语言清晰说明技能的用途，适用场景与能力边界，是模型判断调用时机的核心依据。
2. **参数定义**：明确列出所有入参的名称，数据类型，是否必填与取值说明，等同于技能的入参契约。
3. **执行逻辑**：后端实际运行的代码或接口服务，接收参数，完成执行，返回标准化结果。这部分对模型不可见，仅输出最终执行状态与数据。

以行程场景的景点查询 Skill 为例，标准描述格式如下：

```
技能名称：search_attraction
功能描述：查询指定城市的热门景点信息，返回景点名称，地址，开放时间，门票价格
输入参数：
  - city: string 必填，目标城市名称
  - tag: string 可选，景点类型标签，可选值为古迹，自然，亲子，美食
返回格式：JSON数组，每个元素包含name，address，open_time，price字段
```

### 9.3 技能调用能力的实现

模型无法天然识别技能调用格式，主流实现方式有两种：

1. **微调注入**：构造包含用户需求 - 工具调用指令 - 执行结果 - 最终回答完整链路的样本，通过监督微调将工具调用格式固化到模型权重中，是工业级系统的主流方案。
2. **上下文引导**：在 Prompt 中写入技能描述与调用示例，通过上下文学习让模型临时模仿调用格式，适合快速验证与低频场景。

### 9.4 工业级设计原则

1. **原子化**：单个 Skill 只承担单一职责，功能边界清晰，避免设计大而全的复合技能，降低模型的决策难度。
2. **容错性**：内置参数校验与异常处理逻辑，对格式错误，参数缺失等问题返回明确的错误提示，支撑模型自行修正重试。
3. **结构化返回**：统一使用 JSON 等结构化格式返回结果，避免大段自由文本，降低模型的解析成本与出错概率。
4. **规模可控**：单轮对话开放的 Skill 数量控制在合理范围，可选技能越多，模型错选的概率越高，必要时先做技能分类预选。
