# 第 10 章 智能体 Agent

Agent 是以大模型为核心大脑，自主完成目标拆解，步骤执行，结果校验与错误修正的完整系统。与普通对话模型的单次输出不同，Agent 接收最终目标后自主调度执行流程，无需人工干预中间步骤。

### 10.1 四大核心组件

#### 1. 规划模块

接收目标任务，拆解为多步可执行的子任务，生成整体执行计划；执行过程中遇到异常或分支时，动态调整计划或触发重新规划。

#### 2. 记忆模块

存储任务全链路信息，分为三类：

- 短期记忆：当前任务的对话上下文，执行历史，依托模型上下文窗口承载；
- 长期记忆：历史任务沉淀的经验，用户偏好与知识库内容，存储于外部存储系统；
- 工具记忆：所有可用 Skill 的描述与调用规范。

#### 3. 执行模块

接收模型生成的工具调用指令，完成参数解析，Skill 调度与结果回传，是模型与外部工具之间的交互中间层。

#### 4. 校验模块

每一步执行后校验结果是否符合预期，判断任务是否完成，是否存在错误，是否需要重试或修正，是保证任务成功率的关键。

### 10.2 两种主流实现范式

#### 10.2.1 ReAct 范式

ReAct（Reasoning + Acting）是最基础，落地最广的智能体范式，核心是思考 - 行动 - 观察的串行循环：

- Thought：模型基于当前状态分析，推导下一步行动方向；
- Action：调用对应 Skill，传入参数执行；
- Observation：获取 Skill 执行结果，更新当前状态。

循环往复，直到模型判定任务达成，输出最终结果。
优势是逻辑简单，易于实现，执行过程可解释；缺点是单步串行无全局规划，长链路任务容易出现方向偏移与错误累积。

#### 10.2.2 Plan-and-Execute 范式

该范式将全局规划与分步执行拆分，更适配复杂长流程任务：

- 初始规划：接收任务后先生成完整的多步执行计划，明确各阶段目标与依赖关系；
- 分步执行：按照计划顺序逐次执行，每步完成后做单步校验；
- 动态重规划：遇到计划外情况，执行失败或新增约束时，触发全局计划更新，再继续执行。

优势是长任务稳定性更强，步骤遗漏与逻辑矛盾的概率更低；缺点是实现复杂度更高，重规划的触发条件与粒度需要精细调优。

### 10.3 核心痛点与落地现状

当前通用智能体尚未大规模成熟，核心受限于三个底层问题：

1. **长程规划能力有限**：任务步骤超过 5 步后，计划的完整性，合理性会明显下降，容易出现步骤冗余，顺序错误或逻辑遗漏。
2. **错误累积效应**：串行执行链路中，单步错误会向下传导，模型未必能及时识别并修正，步骤越多，最终成功率越低。
3. **工具幻觉问题**：模型可能虚构不存在的技能，生成非法参数格式或重复无效调用，导致执行卡壳。

工业落地的现状是：开放域通用智能体仍处于探索阶段，但边界清晰，流程固定的场景化智能体已经广泛应用，比如客服工单处理，数据分析助手，代码调试助手等，在限定范围内可以达到很高的执行成功率。
