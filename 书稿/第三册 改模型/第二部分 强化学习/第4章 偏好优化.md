## 4.1 偏好对齐要解决什么问题
SFT通过指令-答案对做监督训练，只能教会模型“按照指定格式回答”，但存在天然局限：
1. **无法处理多答案场景**：同一个问题有多个合理回答，SFT只能拟合其中一种，无法定义优劣标准；
2. **无法对齐主观偏好**：帮助性，安全性，语气风格这类主观诉求，无法用单一标准答案标注；
3. **容易出现模式固化**：SFT拟合标注数据的分布，难以形成稳定，一致的价值取向。

偏好对齐的目标，是在保留基座通用能力的前提下，让模型的输出分布向人类期望的方向偏移，让“更好的回答”出现概率更高，“更差的回答”出现概率更低。

## 4.2 传统对齐范式：RLHF的思路与痛点
经典RLHF（Reinforcement Learning from Human Feedback）分为三步：
1. 监督微调（SFT）：训练出具备基础指令跟随能力的模型；
2. 奖励模型（RM）训练：基于人类标注的成对偏好数据，训练一个给回答打分的奖励模型；
3. PPO强化学习：以奖励模型的分数为反馈信号，用PPO算法优化SFT模型的输出策略，最大化奖励得分。

这套范式在早期闭源大模型上验证了效果，但落地痛点非常突出：
- 链路冗长，需要同时维护SFT模型，奖励模型，PPO训练流程，组件多，调试成本高；
- 训练不稳定，PPO容易出现奖励黑客（模型投机刷分，输出质量下降），模式崩溃等问题；
- 算力开销大，PPO每轮都要做生成，打分，更新，成本远高于监督训练。

## 4.3 DPO：直接偏好优化
DPO（Direct Preference Optimization）是当前工业界的主流对齐方案。它从数学上证明了奖励模型与最优策略的等价性，将RLHF的三步流程压缩为一步：直接用成对偏好数据优化策略模型，省去了独立的奖励模型与PPO环节。

### 4.3.1 核心原理
DPO的核心逻辑非常朴素：对于同一个问题，我们不需要知道回答的绝对分数，只需要让模型提升“偏好回答”的相对概率，降低“非偏好回答”的相对概率，同时保证模型不要偏离原有能力太远。

具体来说，给定同一个提示词$x$，存在两个回答：
- $y_{\text{chosen}}$：人类更偏好的回答
- $y_{\text{rejected}}$：人类更不偏好的回答

DPO引入一个**冻结的参考模型**（通常就是SFT后的基座模型），用来约束训练模型的偏移幅度，避免过度对齐导致通用能力退化。最终的损失函数通过sigmoid函数，将“偏好回答的相对概率优势”转化为二分类损失：
$$
L_{\text{DPO}} = -\mathbb{E}_{(x,y_c,y_r) \sim D} \left[ \log \sigma \left( \beta \cdot \Delta \log \pi(y_c|x) - \beta \cdot \Delta \log \pi(y_r|x) \right) \right]
$$
其中 $\Delta \log \pi(y|x) = \log \pi_\theta(y|x) - \log \pi_{\text{ref}}(y|x)$，各符号含义：
- $\pi_\theta$：当前正在训练的策略模型，参数可更新
- $\pi_{\text{ref}}$：冻结的参考模型，提供基准概率分布
- $\beta$：温度系数，控制对齐的强度，数值越大对齐越激进
- $y_c, y_r$：分别对应偏好回答与非偏好回答

### 4.3.2 直观理解
公式里的对数概率差值，本质就是模型相对于参考模型的“奖励优势”。DPO要做的，就是拉大偏好回答和非偏好回答之间的奖励优势差距，让模型越来越倾向于输出人类偏好的结果。

和RLHF相比，DPO没有显式的奖励模型，也没有强化学习的探索过程，全程就是监督式的损失计算与参数更新，训练稳定性和落地难度大幅降低。

### 4.3.3 核心优势
1. **流程极简**：仅需成对偏好数据，一步完成训练，工程复杂度与SFT相当；
2. **训练稳定**：无PPO的奖励黑客，模式崩溃问题，超参数少，复现性强；
3. **效果对标RLHF**：在帮助性，安全性等主流对齐任务上，效果与调优良好的RLHF持平；
4. **兼容PEFT**：可以和LoRA等参数高效微调方案结合，单卡即可完成7B模型的对齐训练。

## 4.4 DPO的完整训练流程
1. **数据准备**：构造成对偏好数据集，每条样本包含一个prompt，以及对应的偏好回答，非偏好回答；
2. **模型初始化**：以SFT模型作为训练起点，同时复制一份权重作为冻结的参考模型；
3. **损失计算**：对每条样本，分别计算策略模型与参考模型在两个回答上的对数概率，代入DPO损失函数；
4. **参数更新**：反向传播损失，仅更新策略模型的参数，参考模型全程冻结；
5. **效果校验**：通过验证集的偏好准确率，通用能力基准，平衡对齐强度与能力保留。

## 4.5 关键工程细节
- **参考模型的作用**：核心是防止模型过度偏移，保留基座的通用知识与推理能力。没有参考模型约束，模型很容易为了拟合偏好数据，丢失原有能力。
- **\(\beta\)系数选择**：工业界常用取值为0.1~0.5。\(\beta\)越大，对齐强度越高，越容易损失通用能力；\(\beta\)越小，对齐越保守，对原有能力影响越小。
- **数据质量优先**：DPO的效果上限由数据决定。成对样本的偏好差异越明确，标签一致性越高，对齐效果越好；模糊，矛盾的偏好标签会严重损害效果。
- **LoRA适配**：工业界绝大多数DPO训练都会搭配LoRA，仅训练少量低秩参数，进一步降低成本，同时避免全量更新带来的能力退化。

## 4.6 DPO实现

### 训练代码（LoRA版DPO）
```python
import torch
from datasets import Dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from peft import LoraConfig
from trl import DPOTrainer

# ========== 1. 构造成对偏好数据集 ==========
# 同一条prompt，chosen为更优回答，rejected为质量更差的回答
data = [
    {
        "prompt": "五一想去杭州玩三天",
        "chosen": "Day1：西湖环湖线，清晨逛断桥，白堤，午后走苏堤，登雷峰塔，傍晚看湖滨音乐喷泉\nDay2：灵隐寺祈福，下午逛龙井村，走九溪烟树，体验茶园春色\nDay3：逛河坊街与南宋御街，感受老城烟火，午后准备返程",
        "rejected": "杭州三天随便玩就行，西湖去一下，灵隐寺也可以去，其他的看着办。"
    },
    {
        "prompt": "元旦去乌兹别克斯坦撒马尔罕3天，怕冷，喜欢古迹",
        "chosen": "Day1：雷吉斯坦广场，夏伊辛达陵墓，傍晚看夕阳；户外单次停留不超过30分钟\nDay2：古尔埃米尔陵墓，兀鲁伯天文台，了解帖木儿王朝历史\nDay3：布哈拉古城半日游，午后返程",
        "rejected": "撒马尔罕不大，三天时间很充裕，所有景点都可以慢慢逛，不用特意规划。"
    }
]
dataset = Dataset.from_list(data)

# ========== 2. 加载基座与分词器 ==========
model_name = "Qwen/Qwen2-7B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

# 策略模型：挂载LoRA，参与参数更新
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    load_in_4bit=True
)

# 参考模型：权重全程冻结，提供基准概率分布
model_ref = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto",
    load_in_4bit=True
)

# ========== 3. LoRA配置 ==========
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

# ========== 4. 训练参数配置 ==========
training_args = TrainingArguments(
    output_dir="./dpo_travel_assistant",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,
    learning_rate=5e-5,
    num_train_epochs=2,
    logging_steps=10,
    bf16=True,
    optim="paged_adamw_8bit",
    remove_unused_columns=False
)

# ========== 5. 初始化DPOTrainer并启动训练 ==========
dpo_trainer = DPOTrainer(
    model=model,
    ref_model=model_ref,        # 冻结的参考模型
    args=training_args,
    beta=0.1,                  # 对齐强度核心超参数
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=lora_config,   # 启用参数高效训练
    max_prompt_length=128,
    max_length=512
)

dpo_trainer.train()

# ========== 6. 保存LoRA权重 ==========
model.save_pretrained("./dpo_travel_assistant_final")
tokenizer.save_pretrained("./dpo_travel_assistant_final")
```

### 代码关键说明
1. **成对数据格式**：每条样本必须包含`prompt`，`chosen`，`rejected`三个字段，是DPO的标准输入格式；
2. **参考模型**：`ref_model`全程冻结，用于计算基准对数概率，约束模型偏移幅度；
3. **beta参数**：控制对齐强度，是DPO最核心的超参数；
4. **LoRA兼容**：通过`peft_config`传入配置，即可实现参数高效的DPO训练，训练成本与LoRA版SFT接近；
5. **推理方式**：训练完成后，权重加载，合并，推理的流程与LoRA SFT完全一致，可直接复用前文的推理代码。

DPO虽然省去了显式的奖励模型，但它的理论底层仍然建立在奖励建模的逻辑之上。对于更复杂的多维度偏好融合，大规模对齐场景，独立的奖励模型仍然具备不可替代的价值。
