# 第 16 章 Qwen架构解析

现在，让我们一起阅读下2026年中 qwen发布的 Qwen3.8-Flash-Next的架构
这个模型被官方定位成 **Qwen4 架构的预览版**——Qwen3-Next 之于 Qwen3.5 是同样的角色。厂商习惯用一个中等规模的模型先把新架构放出来试水，所以这类"Next / Preview"命名的模型往往比同期的旗舰更值得读。


![Qwen3.8-Falsh-Next](figures/qwen-architecture.png)

## 16.1 总体结构

48 层，按**每 4 层一组**的模式堆叠，每组是 **3 层 Gated DeltaNet + 1 层 Qwen Sparse Attention**，每个注意力/线性层后面都跟一个 MoE。官方模型卡把这个布局写成：

```
12 × ( 3 × (Gated DeltaNet → MoE) → 1 × (Qwen Sparse Attention → MoE) )
```

主干参数 125B，每 token 激活 6B；另外挂了一张 51B 的 n-gram 嵌入表和一个 4B 的 MTP 模块。隐藏维 2560，词表 248320（已 padding），原生上下文 262144，可扩展到 1,000,000。

可以看到
- 它是 **decoder-only**的（第 2 章）
- 用现代稠密配方：RMSNorm，SwiGLU，RoPE，QK-Norm（第 5，6 章）
- 注意力侧走**混合**路线（第 14 章）：多数层线性，少数层精确注意力
- FFN 侧走 **MoE**（第 9 章）
- 输出侧加 **MTP**（第 15 章）


"精确注意力"的内部实现：Qwen3-Next 到 Qwen3.5 这条线上它是**门控注意力**，到 Flash-Next 换成了 **QSA**——在门控注意力的基础上加了块级的重要性筛选，只看选中的微块（第 11 章）。

对照第 12 章线性注意力框架，GDN 前向流程如下：输入经过 RMSNorm，投影得到 query，key，value 与门控信号；借助 delta rule 增量更新固定维度的状态矩阵，由门控控制历史信息的遗忘强度；从状态读取特征后经过输出投影，叠加残差输出。

GDN 采用非对称多头设计：QK 为 16 头，V 为 48 头，所有头的头维均为 128。V 头数是 QK 的三倍，用来拓宽 value 侧的状态空间。正如 12.5 节提到的，这类线性结构的能力上限受限于状态容量，该设计就是对状态容量的定向增强。

## 16.3 QSA

Qwen Sparse Attention，是一套和 GDN 搭配使用的稀疏注意力模块。GDN 依靠固定维度的状态向量，以线性代价长期记忆历史，但只能得到压缩后的摘要，无法精准回溯原始的 token 细节。QSA 就是专门负责**选择性召回原始历史 token，做精细注意力匹配**的组件。

整体分成两条并行分支：indexer 索引分支，主注意力分支。

indexer 是轻量化的检索子网络，采用 MQA 结构：4 个 query 头，1 个共享 key 头，头维 128。它不直接在 token 粒度做相关性计算，而是先把输入序列切分成固定大小的微块，对块内 key 做聚合，在块层面计算相似度打分，挑选相关性最高的若干块。整套检索设置硬预算上限：最多选取 512 个微块，等价于 2048 个 token，对应每块包含 4 个 token。选出的块还原回内部原始 token，送入主分支计算精细注意力。
indexer 本身和模型一同训练，属于可学习的检索器。它的核心思路是用廉价的块粗筛，规避对全部历史 token 做昂贵的稠密注意力；同时有天然的权衡：索引带来的额外 KV 缓存与打分开销，必须小于主分支节约下来的算力，也就是第 11.4 节所说可学习检索式稀疏注意力的实例。

主分支是带输出门控的 GQA 注意力：一共 24 个 query 头，2 组 KV 头，每 12 个 query 头共享一组 KV，头维度 256。这里采用部分维度 RoPE 方案：只在其中 64 维添加旋转位置编码，剩下 192 维不携带位置信息，对应第 6 章的设计，目的是缓解超长上下文下的位置外推衰减，提升长度泛化能力。

这套结构最关键的特性是算力预算隔离：**主分支稠密注意力的计算量被预算封顶**。无论输入上下文是几十万还是一百万 token，每个 query 只和最多 2048 个召回的 token 执行高开销的精细注意力，这是它支撑百万级超长上下文的核心原因

## 16.4 MoE 与路由配置

**512 个专家，每 token 激活 10 个路由专家 + 1 个共享专家，专家中间维 640**，配免辅助损失的偏置调节（第 9.4 节）。


每个专家是一个 SwiGLU FFN（三个矩阵：gate，up，down），隐藏维 2560，中间维 640：

`3 × 2560 × 640 ≈ 4.92M` 参数/专家

每层 512 个专家：

`512 × 4.92M ≈ 2.52B` 参数/层

48 层：

`48 × 2.52B ≈ 121B`

加上注意力层，嵌入和归一化，正好对上官方公布的 **125B**。可以看到，MoE 的 FFN 占了这个模型 96% 以上的参数。

再算激活的部分。每 token 走 11 个专家（10 路由 + 1 共享）：

`11 × 4.92M ≈ 54M` 参数/层 → `48 × 54M ≈ 2.6B`

加上注意力与嵌入部分，约 **6B**，与官方数字一致。


## 16.5 n-gram

51B 的 n-gram 嵌入表是这个模型独特的地方：**两千万个 bigram / trigram 条目，在第 2 层做查表注入**。由参数量反算：

\[
20{,}000{,}000\times2560
=51.2\text{B},
\]

主体就是一张“约两千万条目 × 隐藏维 2560”的大表。输入序列先形成 bigram/trigram 的离散索引，再查出与主干同维的向量，在浅层注入残差流。它不是对全文做向量检索，而是用短 n-gram ID 直接寻址，因此计算接近普通 embedding lookup。

在增大模型参数的操作中加层数更贵，加专家占用更多通信，而加嵌入表只是查表操作，几乎不增加计算量，而且可以放到 CPU 内存里按需取，对显存受限的部署特别友好。官方的说法就是"嵌入提供了一条独特的参数扩展轴"。


## 16.6 MTP

主干之后挂1 层 MTP 模块，用多步方式训练，参数量 4B。训练时提供额外的监督信号，推理时作为草稿头驱动投机解码。

## 16.7 对比

**对比同等激活量的稠密模型**

一个 6B 的稠密模型，权重显存 12 GB，每 token 也是约 12 GFLOPs。

| | 6B 稠密 | Qwen3.8-Flash-Next |
|---|---|---|
| 权重显存 | 12 GB | 250 GB（约 21 倍） |
| 每 token 计算量 | ≈ 12 GFLOPs | ≈ 12 GFLOPs（持平） |
| 质量 | 6B 水平 | 远高于 6B |
| 长上下文成本 | 稠密 attention 平方增长 | 近线性索引 + 固定预算精算 |

## 核心问答

**Q1：为什么 3 层 GDN 配 1 层注意力，而不是别的比例？**
因为 GDN 省得多但记不住细节，注意力准但贵，3:1 是在它们的目标场景上试出来的平衡点（第 14.2 节）。它是一个工程选择，不是理论结论——MiniMax-01 用过 7:1，Gemma 2 用过 1:1，都合理。不过到 2026 年，3:1 附近已经是几家旗舰的共同选择了（附录 D.4）。

**Q2：这个模型的 KV 显存怎么算？**
只统计 12 层 QSA，套第 4 章的公式：每 token 每层 2 KB，全模型 24 KB，262K 上下文约 6 GB。GDN 层只有与长度无关的固定状态。这是它能开超长上下文的直接原因。

**Q3：它是 MoE 模型，我需要多少显存才能跑？**
主干按**总参数**算：125B × 2 字节 = 250 GB（不是按 6B 激活参数算），再加 KV 和框架开销。n-gram 表那 102 GB 可以卸到 CPU。MoE 的稀疏只降低计算量，不降低显存需求（第 9.6 节）。

**Q4：QSA 会不会选错块，把重要信息漏掉？**
会，这是稀疏注意力固有的失效模式（第 11.5 节）——一旦某个块没被选中，它就完全不参与计算，不像线性注意力那样只是变糊。缓解手段是 indexer 和主干一起训练（让选择策略自己学好），以及总是保留最近的块。**判断一个稀疏注意力模型好不好用，要看它在"大海捞针"这类精确检索任务上的表现，不能只看困惑度**。

**Q5：GDN 层在训练和推理时是同一套代码吗？**
不是。训练走分块并行以保证效率，推理走逐 token 状态更新以保证低延迟，两条路径必须数值等价。这是实现这类模型时最容易出错的地方。

**Q6：下一代模型出来，这一章还有用吗？**
16.8 表格的左列有用，右列会过期。这也是本书把它放在最后一章而不是当成主线的原因——**你要带走的是左列，以及 16.4 那套手算参数量的方法。**
