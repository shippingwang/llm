# 第 15 章 投机解码


大模型常规自回归生成，是**一个 token 算一次**。每生成一个 token，GPU 都要重新把模型权重从显存读到计算单元。小批量场景下，GPU 算力经常空着，大部分时间都耗在反复搬运权重上，访存拖慢了整体速度。

既然读权重很贵，那能不能读一次权重，一次性确认好几个 token？这就是投机解码最原始的想法。
但自回归有个约束：后面 token 依赖前面的输出，没法直接并行算出未来 token。所以思路拆成两步：先用低成本方式 “猜” 后面一串 token，再交给主模型一次性批量校验这批猜测结果。猜对就直接收下，猜错就停在出错位置，重新采样

## 15.1 核心流程

一轮循环分为两步：

1. **草稿生成**：用低成本模块一次性预测后续连续 k 个候选 token。
2. **验证**：把这 k 个候选拼接成序列送入目标模型做单次前向。候选序列已知，所有位置可以并行算出目标模型的输出分布，再按接受规则判定。

贪心解码场景，可以简单对比草稿 token 和目标模型 argmax 结果；采样生成不能用这个简化判断。
设草稿分布为 \(q(x)\)，目标模型分布为 \(p(x)\)，草稿 token \(x\sim q\) 的接受概率：
\(a(x)=\min\left(1,\frac{p(x)}{q(x)}\right).\)
一旦拒绝该 token，丢弃后面全部草稿，从修正分布

\[
p'(x)=
\frac{[p(x)-q(x)]_+}
{\sum_y[p(y)-q(y)]_+}
\]

重新采样。这套接受 - 修正机制是保证**最终输出严格服从目标分布 p** 的关键。工程实现如果采用近似接受规则，tokenizer 不一致，或是省略重采样修正，无损质量的数学保证就不再成立。

加速上限由草稿接受率决定。猜测越准，单次前向能确认的 token 越多，常见实测加速区间 2–3 倍。接受率过低时，验证开销反而拖累整体速度。

## 15.2 草稿

- **小模型**：投机解码的经典原生方案，通过独立小模型自回归生成草稿，再由大模型单次前向完成批量验证。实现逻辑简单，但需额外加载小模型，接受率高度依赖大小模型的分布贴合度。
- **Medusa**：在已训练大模型主干上外挂多个并行预测头，分别预测\(t+2，t+3\)等后续位置 token。无需额外部署第二模型，工程落地成本低，是工业界应用最广的轻量化方案。
- **Eagle**：主干模型只做一次前向，输出当前位置的隐藏特征 \(h_t\)，之后主干不再执行。它外挂一个轻量的推演分支，主干权重全程冻结，仅单独训练该分支；训练时用主干真实输出的后续隐藏特征做监督，教会分支链式外推时序特征：把上一步预测出来的特征送入这个轻分支，得到下一步的预测特征，反复迭代得到 \(h_{t+1},h_{t+2},h_{t+3}\dots\)。全部推演都在这个廉价分支上完成，不再调用主干 Transformer。最后把这一串预测特征统一送入主干自带的 LM 头，翻译成一串候选 token 草稿。主干执行一次批量前向，顺序校验这串 token，找到第一个不匹配的位置截断，前面连续匹配的 token 直接生效。相比 Medusa 独立并行预测 token，Eagle 保留时序依赖，草稿连贯性更强，接受率更高。注意和原生 MTP 区分：MTP 在预训练阶段和主干一起联合训练；Eagle 的分支属于后训外挂模块，主干固定不变

## 15.3 MTP

Medusa，Eagle，小模型草稿都属于**训练完成后外挂的推理加速手段**。MTP（Multi-Token Prediction，多令牌预测）思路更进一步：**预训练阶段就同时学习预测未来多个 token**。

主头负责预测 \(x_{t+1}\)，额外增加 \(D-1\) 个预测头，损失定义：

\[
\mathcal L_{\text{MTP}}
=\sum_{d=1}^{D}\lambda_d
\left[
-\sum_t\log p_\theta^{(d)}
(x_{t+d}\mid x_{\le t})
\right]
\]

核心约束：第 d 个预测头，只能使用位置 t 处的隐藏状态，**不允许利用 \(t+1\) 到 \(t+d-1\) 的中间 token**。举个例子，输入序列 `Birds sing up in the tree`，在读到 `Birds`（位置 t）时：预测 t+2 位置的`up`，不能依赖中间词`sing`，只能单凭`Birds`的特征直接跳着预测。不同实现对权重共享，预测头结构的设计各不相同，MTP 不是一套固定架构。

MTP 带来两层收益：

- **训练侧**：多步预测提供更多监督信号，有可能学习到更长距离表征。但收益受 \(\lambda_d\)，预测深度，训练配方影响，不是必然提升主任务效果。
- **推理侧**：训练好的多预测头可以直接输出草稿候选，交给主模型验证。能否落地，取决于推理引擎是否支持树状候选，KV 缓存复用与完整的接受重采样逻辑。

这里我觉得MTP之所以有效是对大量语料的估计，即在语言学上，跳着读跳着写也是可行的，因为有很大一部分语句是冗余的。

## 核心问答

**Q1：投机解码会降低生成质量吗？**
正确实现接受 - 重采样规则时，输出分布和普通逐 token 生成完全一致，只加速，不引入近似。工程简化实现会破坏这个性质。

**Q2：加速比由什么决定？**
草稿接受率，加上草稿本身的推理开销。举例：单次生成 5 个草稿 token，平均接受 3 个，等效一次前向产出 3 个 token。接受率太低时验证开销会减速。

**Q3：MTP 和 Medusa 的本质区别？**
经典 Medusa 一般冻结主干，只微调新增的未来 token 头；MTP 是预训练联合优化多步预测目标，主干参数同样接收多步预测梯度。Medusa 改造成本更低；MTP 有机会学到更适配多步预测的表征，但性能提升需要消融验证，不是定义自带的增益。

**Q4：为什么说 MTP 不只是推理加速手段？**
MTP 修改训练目标与梯度信号，不是仅改动推理调度逻辑。多步监督有可能提升表征质量与样本效率；参数配置不当也会干扰 next-token 主目标。评估必须同时看主 loss，下游任务精度，草稿接受率三项指标。

**Q5：投机解码和 MoE 可以叠加吗？**
可以，二者正交互补。MoE 降低单 token 计算开销；投机解码分摊权重访存开销，一次加载权重产出更多 token。前沿大模型常把两者组合使用。

**Q6: MTP 各个预测头并行独立，只用同一个 \(h_t\) 直接跳着预测后面多个 token，没有中间 token 做条件，凭什么还能用？**

它本身就很难次次猜对，本来就不追求跳步预测必须精准。
第一，训练时靠损失权重 \(\lambda_d\) 做取舍：优先保证 t+1 主头效果，越远的预测头分配越低的损失权重，不强求远距离预测准确；
第二，它的输出定位只是投机解码的草稿，不是直接采信的结果，主干模型会逐 token 校验，错了就截断；
第三，它依靠预训练学到的文本局部共现统计先验，存在一定概率连续猜对一小段，只要能命中一小段，就能节省主干前向，拿到吞吐收益。
