# 第 3 章 组装训练

这一章我们补齐训练流程，看一看实际操作是怎样的，利用训练框架实现的上一章介绍的语言模型组件，把他们拼在一起构成整体训练系统，当然也包括简单的推理，如果你对工程设计和代码不感兴趣，可以跳过本章。

## 3.1 数据

磁盘上的普通文本 

```text
hello world
hello torch
```

编码之后得到一串整数。训练时从这串整数上切长度为 `block_size` 的窗口。设 `block_size = 8`，某次切到 ID：

```text
idx    = [h e l l o   w o]     形状 [B, 8]，送进模型
目标   = [e l l o   w o r]     形状 [B, 8]，与 idx 错开一位
```

实现上不必另存一份已经错开的张量：`idx` 与 `labels` 取同一窗口，在 loss 里做 `logits[:, :-1]` 对 `labels[:, 1:]`。位置 0 的分布去拟合 `e`，位置 6 的分布去拟合 `o`，最后一个位置的 logits 没有下一位标签，直接丢掉。

有padding时，补出来的位置在 `labels` 里写成 `-100`。`F.cross_entropy(..., ignore_index=-100)` 不给这些位置梯度。本例的随机切片没有 pad，标签里全是真实字符。

```python
import math
from dataclasses import dataclass

import torch
import torch.nn as nn
import torch.nn.functional as F


class CharTokenizer:
    """从语料统计字符表。正式训练换 BPE 时，只替换 encode/decode 与 vocab_size。"""

    def __init__(self, text: str):
        chars = sorted(set(text))
        self.stoi = {ch: i for i, ch in enumerate(chars)}
        self.itos = {i: ch for ch, i in self.stoi.items()}

    @property
    def vocab_size(self) -> int:
        return len(self.stoi)

    def encode(self, s: str) -> list[int]:
        return [self.stoi[c] for c in s]

    def decode(self, ids: list[int]) -> str:
        return "".join(self.itos[i] for i in ids)


def sample_batch(token_ids: torch.Tensor, batch_size: int, block_size: int, device: torch.device):
    """token_ids: 整份语料的一维 LongTensor。返回 idx, labels，形状都是 [B, block_size]。"""
    # 窗口右端还要能取到「下一位」，所以起点上限是 len - block_size - 1
    hi = token_ids.numel() - block_size - 1
    if hi <= 0:
        raise ValueError("语料短于 block_size+1，无法切出一个带标签的窗口")
    starts = torch.randint(0, hi, (batch_size,))           # 每条样本一个随机起点
    windows = torch.stack([token_ids[s : s + block_size] for s in starts.tolist()])
    return windows.to(device), windows.to(device)          # idx 与 labels 同一窗口；错位在 loss 里做
```

语料至少要比 `block_size` 长出 1 个 token，否则没有下一个字可监督。

> 这份代码 过拟合演示用几 KB 文本即可；拿它衡量生成质量是没有意义的，只用来确认前向反向走得通。

## 3.2 模型

因果掩码注册成 buffer。`scaled_dot_product_attention(..., is_causal=True)` 与手写上三角 `-inf` 一致；

```python
@dataclass
class GPTConfig:
    vocab_size: int
    block_size: int = 128
    n_layer: int = 4
    n_head: int = 4
    n_embd: int = 128
    dropout: float = 0.0
    tie_embeddings: bool = True


class CausalSelfAttention(nn.Module):
    def __init__(self, cfg: GPTConfig):
        super().__init__()
        assert cfg.n_embd % cfg.n_head == 0
        self.n_head = cfg.n_head
        self.d_h = cfg.n_embd // cfg.n_head
        self.qkv = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=False)
        self.proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=False)
        self.drop = nn.Dropout(cfg.dropout)
        # 上三角（不含对角线）为 True：这些位置在 softmax 前填 -inf
        mask = torch.triu(torch.ones(cfg.block_size, cfg.block_size, dtype=torch.bool), diagonal=1)
        self.register_buffer("causal", mask, persistent=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, n, _ = x.shape                                    # x: [B, n, d]
        qkv = self.qkv(x).view(B, n, 3, self.n_head, self.d_h).permute(2, 0, 3, 1, 4)
        q, k, v = qkv[0], qkv[1], qkv[2]                   # 各 [B, h, n, d_h]；无 cache，用完即丢
        att = (q @ k.transpose(-2, -1)) * (self.d_h ** -0.5)  # [B, h, n, n]
        att = att.masked_fill(self.causal[:n, :n], float("-inf"))  # 看不见未来
        att = self.drop(att.softmax(dim=-1))
        y = (att @ v).transpose(1, 2).contiguous().view(B, n, -1)  # 拼回 [B, n, d]
        return self.proj(y)


class MLP(nn.Module):
    def __init__(self, cfg: GPTConfig):
        super().__init__()
        self.fc = nn.Linear(cfg.n_embd, 4 * cfg.n_embd, bias=False)
        self.proj = nn.Linear(4 * cfg.n_embd, cfg.n_embd, bias=False)
        self.drop = nn.Dropout(cfg.dropout)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.drop(self.proj(F.gelu(self.fc(x))))


class Block(nn.Module):
    """Post-LN：x = LN(x + Attn(x))，再 x = LN(x + MLP(x))。"""

    def __init__(self, cfg: GPTConfig):
        super().__init__()
        self.attn = CausalSelfAttention(cfg)
        self.mlp = MLP(cfg)
        self.ln1 = nn.LayerNorm(cfg.n_embd)
        self.ln2 = nn.LayerNorm(cfg.n_embd)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = self.ln1(x + self.attn(x))
        x = self.ln2(x + self.mlp(x))
        return x


class GPT(nn.Module):
    def __init__(self, cfg: GPTConfig):
        super().__init__()
        self.cfg = cfg
        self.tok_emb = nn.Embedding(cfg.vocab_size, cfg.n_embd)
        self.pos_emb = nn.Embedding(cfg.block_size, cfg.n_embd)
        self.drop = nn.Dropout(cfg.dropout)
        self.blocks = nn.ModuleList(Block(cfg) for _ in range(cfg.n_layer))
        self.ln_f = nn.LayerNorm(cfg.n_embd)
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        if cfg.tie_embeddings:
            self.lm_head.weight = self.tok_emb.weight
        self.apply(self._init_weights)

    @staticmethod
    def _init_weights(m: nn.Module) -> None:
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx: torch.Tensor, labels: torch.Tensor | None = None):
        B, n = idx.shape                                     # idx: [B, n]
        if n > self.cfg.block_size:
            raise ValueError(f"n={n} 超过 block_size={self.cfg.block_size}")
        pos = torch.arange(n, device=idx.device)             # 位置 0..n-1
        x = self.drop(self.tok_emb(idx) + self.pos_emb(pos))  # → [B, n, d]
        for block in self.blocks:                            # L 层，形状一直 [B, n, d]
            x = block(x)
        logits = self.lm_head(self.ln_f(x))                  # → [B, n, V]
        loss = None
        if labels is not None:                               # 训练才算 loss；生成不传 labels
            loss = F.cross_entropy(
                logits[:, :-1].reshape(-1, logits.size(-1)),  # 预测：前 n-1 个位置
                labels[:, 1:].reshape(-1),                    # 标签：后 n-1 个 token（错开一位）
                ignore_index=-100,
            )
        return logits, loss
```


我们看下网络中的数据形状

- **入口**：输入 token id，查表拿到 d 维向量。参数矩阵形状：`[V, d]`，V 词表大小，d 隐藏维度。作用：id → 向量。
- **出口**：最后一层的隐状态 h（d 维），要算出每个词的分数 logits。它本质是一个无偏置线性层 `Linear(d, V)`，权重矩阵 `lm_head.weight` 形状也是 `[V, d]`。
所以会出现两张同形的表。可以少存一份 \(Vd\) 参数，输入输出共用同一套词向量

```python
self.lm_head.weight = self.tok_emb.weight
```

GPT-2 一类默认打开

与 `apply(_init_weights)` 的顺序：上面代码先绑定，再 `apply` 共享后同一块权重可能被初始化写两次（Embedding 分支一次，Linear 分支一次），分布都是 \(N(0,0.02)\)，留下最后一次。若先 `apply`，再绑定，会先初始化两块，绑定后丢掉 `lm_head` 私有的那份。两种最终都是一份共享权重；书里固定为先绑定，再统一初始化。

## 3.3 训练细节

一步里的顺序是固定的：取 batch → 前向出 loss → `zero_grad` → `backward` → 看梯度范数 → 超过上限则裁剪 → `optimizer.step`。学习率写在参数组上，AdamW 下一步就用新值。

| 配置项 | 这里的取值 | 作用 |
|---|---|---|
| AdamW `lr` | `3e-4`，前 100 步线性抬升 | 小模型字符级过拟合的常用起点 |
| `betas` | `(0.9, 0.95)` | 二阶矩衰减比 CV 里常见的 0.999 更短，大模型训练里更常见 |
| `weight_decay` | `0.1` | 只衰减矩阵权重；AdamW 把衰减从梯度更新里拆开 |
| `clip` | `1.0` | 全局梯度 L2 范数上限 |
| `dropout` | `0` | 先过拟合一小份文本，确认实现；正则留到数据变大之后 |

```python
def learning_rate(step: int, warmup: int, max_lr: float) -> float:
    # step 从 0 计；第 0 步也给一个非零 lr，避免整步梯度被乘成 0
    if step < warmup:
        return max_lr * (step + 1) / warmup
    return max_lr


def train(model: GPT, token_ids: torch.Tensor, steps: int, batch_size: int,
          max_lr: float = 3e-4, warmup: int = 100, clip: float = 1.0) -> None:
    device = next(model.parameters()).device
    block = model.cfg.block_size
    # 矩阵/嵌入做 weight decay；LayerNorm 的一维 γ，β 不做
    decay_params, nodecay_params = [], []
    for name, p in model.named_parameters():
        if not p.requires_grad:
            continue
        (decay_params if p.ndim >= 2 else nodecay_params).append(p)
    opt = torch.optim.AdamW(
        [
            {"params": decay_params, "weight_decay": 0.1},
            {"params": nodecay_params, "weight_decay": 0.0},
        ],
        lr=max_lr,
        betas=(0.9, 0.95),
    )
    model.train()
    for step in range(steps):                              # ① 每个 step 更新一次参数
        lr = learning_rate(step, warmup, max_lr)           # ② warmup 内抬升学习率
        for group in opt.param_groups:
            group["lr"] = lr
        idx, labels = sample_batch(token_ids, batch_size, block, device)  # ③ 切一批 [B, T]
        _, loss = model(idx, labels=labels)                # ④ 前向 + 交叉熵（内部已错开一位）
        opt.zero_grad(set_to_none=True)                    # ⑤ 清梯度
        loss.backward()                                    # ⑥ 反传
        grad_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), clip)  # ⑦ 裁剪
        opt.step()                                         # ⑧ AdamW 更新权重
        if step % 50 == 0 or not math.isfinite(loss.item()):
            print(f"step {step:4d}  lr {lr:.2e}  loss {loss.item():.4f}  grad {grad_norm:.2f}")
        if not math.isfinite(loss.item()):
            raise RuntimeError("loss 变成 NaN/Inf，停止。先把 max_lr 降一个数量级再查掩码与 shift")
```


## 3.4 指标

因为我们的代码趋近于实验性质，属于可运行但是不可用于真实数据的状态，所以

loss 一开始就是 NaN， 学习率过大（例如直接 `1e-2` 且没有 warmup），或注意力分数在 softmax 前溢出。
loss 降得异常快却过拟合，数据只有几 KB，过拟合是预期结果。可以证明反传成功了，但是模型不会写新句子
loss 几乎不降
生成重复同一个字，温度过低（接近贪心）加上模型还没训够，会不断停留在高频字符上。先看训练 loss 是否已经低于「均匀猜字符」的 \(\ln V\)：字符表大约 50 时，\(\ln 50\approx 3.9\)，loss 还在 3.5 附近就不要指望连贯句子。
位置一对不上。 `n > block_size` 时 `pos_emb` 没有对应行直接抛错。把长文截到 `block_size`，想训更长窗口，先加大 `block_size` 并重新初始化位置表，旧位置权重不能假设能外推。


## 3.5 推理


```python
@torch.no_grad()
def generate(model: GPT, idx: torch.Tensor, max_new: int, temperature: float = 0.8) -> torch.Tensor:
    model.eval()
    for _ in range(max_new):                          # ① 循环 max_new 次 → 写出 max_new 个 token
        ctx = idx[:, -model.cfg.block_size :]          # ② 当前前缀（超长则只留最后 T 个）
        logits, _ = model(ctx)                         # ③ 整段 ctx 再跑一遍完整前向
        logits = logits[:, -1, :] / temperature        # ④ 只要最后一个位置的词表分数
        probs = logits.softmax(dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)  # ⑤ 抽出 1 个新 id
        idx = torch.cat([idx, nxt], dim=1)             # ⑥ 拼回前缀，下一轮再用
    return idx
```

本章词表是字符级，一个 token 往往就是一个字符；换成 BPE 后仍是每次一个 token，只是一个 token 可能对应多个字符，可以手动走几遍这个循环看一下生成的流程。

```python
def main() -> None:
    raw = open("input.txt", encoding="utf-8").read()
    tok = CharTokenizer(raw)
    token_ids = torch.tensor(tok.encode(raw), dtype=torch.long)
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    cfg = GPTConfig(vocab_size=tok.vocab_size, block_size=64, n_layer=4, n_head=4, n_embd=128)
    model = GPT(cfg).to(device)
    n_param = sum(p.numel() for p in model.parameters())
    print(f"device={device}  vocab={cfg.vocab_size}  params={n_param/1e6:.2f}M")
    train(model, token_ids, steps=300, batch_size=16)   # 训练
    prompt_ids = tok.encode(raw[:16])
    prompt = torch.tensor([prompt_ids], dtype=torch.long, device=device)
    out = generate(model, prompt, max_new=120, temperature=0.8)  # 自回归续写 120 个 token
    print(tok.decode(out[0].tolist()))


if __name__ == "__main__":
    main()
```


## 3.6 张量

我们看下张量形状

记：\(B\) batch，\(n\) 当前序列长（训练时常等于 `block_size` \(T\)），\(V\) 词表，\(d\) 即 `n_embd`，\(h\) 头数，\(d_h=d/h\)，\(L\) 层数。

前向主线：

| 位置 | 形状 |
|---|---|
| `idx` | \([B,n]\) |
| 嵌入相加后的 \(x\) | \([B,n,d]\) |
| \(Q,K,V\)（每层） | 各 \([B,h,n,d_h]\) |
| 注意力分数 | \([B,h,n,n]\) |
| 注意力 / MLP / 残差干线 | 回到 \([B,n,d]\) |
| MLP 中间 | \([B,n,4d]\) |
| `logits` | \([B,n,V]\) |
| loss 用的切片 | 预测 \([B,n-1,V]\)，标签 \([B,n-1]\) |

残差干线上第三维始终是 \(d\)；头内是 \(d_h\)，FFN 里临时 \(4d\)

存下来的可训练参数（激活每步重算，不进权重文件）
`tok_emb` \([V,d]\)，
`pos_emb` \([T,d]\)，
每层 `qkv` \([3d,d]\) + 输出投影 \([d,d]\)，
每层 MLP `fc` \([4d,d]\) + `proj` \([d,4d]\)。

打开嵌入绑定时 `lm_head` 与 `tok_emb` 同一份，参数只计一次。
LayerNorm 的 \(\gamma,\beta\) 也是参数，量比较小，这里略过。

## 核心问答

**Q1：`idx` 和 `labels` 为什么可以是同一块窗口？**
因为错位发生在 loss 内部：用前 \(n-1\) 个位置的 logits 去拟合后 \(n-1\) 个 token。若 DataLoader 已经给出 `labels = idx` 向左移一位并在末尾补 `-100`，模型里就不能再切一次 `[:, 1:]`。

**Q2：交叉熵里的 `reshape(-1, V)` 在做什么？**
`logits[:, :-1]` 是 `[B, n-1, V]`。`cross_entropy` 要求预测为 `[N, V]`，目标为 `[N]`。把 batch 和长度折到同一维，等价于对所有有效位置求平均，不需要手写双重循环。

**Q3：`ignore_index` 会让 loss 的分母变小吗？**
会。被忽略的位置不进入平均。若一个 batch 里有效标签一个都没有，PyTorch 的交叉熵得到 NaN。padding 比例极高时要检查是不是整批都被标成了 `-100`。

**Q4：为什么 LayerNorm 参数不做 weight decay？**
衰减把参数往 0 拉。矩阵权重上这是正则；LayerNorm 的缩放若被拉向 0，这一层的输出幅度会被人为压扁，和「把激活拉回稳定尺度」的用途相反。所以一维参数放进 `weight_decay=0` 的那一组。

**Q5：`pos_emb` 用下标 `0..n-1`，和 token 的 ID 有关吗？**
无关。位置表按窗口内的序号查行，token 表按字符 ID 查行，两者相加。同一字符出现在窗口的不同列，拿到的位置向量不同。

**Q6：打开 dropout 之后，训练 loss 和重新前向的 loss 对不上？**
训练态下 dropout 每次掩码不同，同一条 `idx` 两次前向 loss 可以差一截。对照实现时用 `model.eval()`，或把 `dropout` 设为 0。

**Q7：`zero_grad(set_to_none=True)` 和置零有什么差别？**
`set_to_none` 把 `.grad` 设成 `None`，下一步 `backward` 直接写入，少一次把梯度缓冲填 0 的读写。语义上本步梯度不与上步相加。若你依赖梯度累积（多步 `backward` 再一次 `step`），中途不能 `zero_grad`。

**Q8：绑定词嵌入之后，参数量怎么数？**
`lm_head.weight` 与 `tok_emb.weight` 是同一对象，`parameters()` 只计一次。手算是 \(V \times d\) 而不是 \(2Vd\)，再加上位置表 \(block\_size \times d\) 和各层投影。

**Q9：温度设成 0 会怎样？**
`logits / temperature` 会除零。贪心应改成 `logits.argmax`，不要把温度写成 0。温度远大于 1 时分布趋近均匀，续写接近从词表里乱抽。

**Q10：这份代码和 HuggingFace `GPT2LMHeadModel` 差在哪？**
差在层的细节：这里是 Post-LN，可学习绝对位置，GELU 两层 FFN，字符词表。训练环（shift 交叉熵，AdamW，裁剪，按步改学习率）同一结构。读开源 `forward` 时，先找 `labels` 是否在内部 shift，pad 是否为 `-100`。
