# 第 7 章 KV Cache 优化


在标准多头注意力（MHA）里，每个 Q 头都配一个自己的 K 头和 V 头。KV 显存 = `2 × 2 × L × h × d_h × n × B`。

\[
Q,K,V\in\mathbb R^{B\times h\times n\times d_h}.
\]

以 32 头，36 层，head_dim 128 的模型算：每 token 每层 16 KB，全模型 576 KB/token，32K 上下文单请求就是 19 GB



## 7.1 MQA

所有 Q 头共用一组 K/V。KV 显存直接除以头数，32 头就是省 32 倍。

此时 \(Q\in\mathbb R^{B\times h\times n\times d_h}\)，而 \(K,V\in\mathbb R^{B\times1\times n\times d_h}\)，计算时把同一组 K/V 广播给所有 Q 头。但是所有头共享同一套“索引和内容”，模型泛化性低。


## 7.2 GQA
多头注意力 MHA 的痛点：KV 缓存开销和 Q 头数量成正比，长上下文推理时显存压力很大。
GQA 是一个折中方案：把全部 Query 头划分成若干组，同一组里所有 Q 头共用同一套 KV 头。

\[
n_{\mathrm{kv}} \le h
\]

GQA 只定义 Q，KV 头之间的分组复用关系。它和 QK-Norm，RoPE，支路入口 RMSNorm 互相正交，可以自由组合在同一条注意力支路里。

设总 Query 头数为 \(h\)，KV 头数量为 \(n_{\mathrm{kv}}\)，每组包含的 Q 头数量：

\[
g = \frac{h}{n_{\mathrm{kv}}}
\]

KV 缓存大小相对 MHA 缩小为原来的 \(1/g\)。
举例：\(h=32,\ n_{\mathrm{kv}}=8\)，也就是每 4 个 Q 头共享一组 KV，KV 缓存只有原版 MHA 的 1/4，精度下降很小，基本感知不到。

张量形状流程：
```
q_proj → [B, n, 32, 128]
k_proj → [B, n,  8, 128]
v_proj → [B, n,  8, 128]
          ↓ kernel 内部映射：q_head // g 去找对应的 kv head
逻辑等价 K/V → [B, n, 32, 128]
```
> 高性能内核不会真的复制多份 KV，只是在取数的时候，用 Q 头编号整除分组数，索引到对应的 KV。
> 如果是手写验证代码，可以用 `repeat_interleave` 来模拟这个逻辑；但一定要核对张量排布是 `[B,n,h,d_h]` 还是 `[B,h,n,d_h]`。轴顺序搞错，形状看着没问题，注意力分数直接错位。

工程上经常选 \(n_{\mathrm{kv}}=8\)，是出于张量并行的便利：如果并行路数刚好也是 8，每张卡拿到整数组 KV，不需要跨卡复制。但这不是硬性规定，\(n_{\mathrm{kv}}\) 需要同时在消融实验里权衡**生成质量，显存占用，部署并行度**。
三者平衡很好，所以 2023 年后新模型基本默认 GQA。

## 7.3 MLA

DeepSeek 的思路不是减少头数，而是把 K/V 投影到一个低维隐向量上，缓存里只存这个隐向量，用的时候再升维还原。

若把所有头拼接后的 KV 记为 \(k_t,v_t\)，MLA 先缓存低维向量

\[
c_t^{KV}=W^{DKV}h_t,\qquad
k_t^C=W^{UK}c_t^{KV},\quad
v_t^C=W^{UV}c_t^{KV}.
\]

缓存从每 token 的 \(2h d_h\) 个元素变成约 \(d_c\) 个元素（外加一小段位置相关 key）。推理时无需真的完整还原：例如

\[
q_t^\top W^{UK}c_s^{KV}
=\left((W^{UK})^\top q_t\right)^\top c_s^{KV},
\]

可把上投影吸收到 query 一侧。这就是“矩阵吸收”省掉显式升维的原因。

RoPE 是位置相关变换，无法同固定的 \(W^{UK}\) 一起预先吸收，因此每头拆成“带 RoPE 的小部分 + 不带 RoPE 的压缩部分”。MLA 可以比 GQA 压得更狠，同时保留更丰富的头级表示；代价是训练，缓存布局和 kernel 都更复杂，这也是它没能像 GQA 一样普及的主要原因。

## 7.4 跨层共享

注意到相邻层的注意力模式高度相似，那就让若干层复用同一份 KV（CLA，YOCO 等）。显存按共享层数成比例下降，且与 GQA / MLA 完全正交，可以叠加。

这里要区分两种做法：跨层注意力（CLA）让一组相邻层直接复用某层产生的 K/V；YOCO 类结构把网络拆成 self-decoder 与 cross-decoder，让后半段跨层复用前半段生成的全局 KV。前者改动小，后者能把 prefill 与缓存复用做得更彻底，但层之间耦合更强。这是 2024 年之后进入主流视野的方向，在端侧和超长上下文场景里尤其有吸引力。

## 核心问答

**Q1：GQA 的分组数为什么常取 8？**
它是常见经验点，不是通用最优值：不少配置在 8 个 KV 头附近能兼顾质量与缓存，而 8 路张量并行也容易切分。实际要同时满足 `n_kv` 整除/兼容 TP，KV 预算和质量消融。

**Q2：MQA 到底差在哪？**
所有 Q 头共享一份 K/V，压缩最激进，因此头级 K/V 表达容量最小。它不等于多头完全失效——Q 头仍然不同——但在部分长文本和检索任务上更容易掉点；是否明显必须看模型和训练方法。

**Q3：MLA 缓存的到底是什么？**
是一个低维隐向量（DeepSeek-V3 里是 512 维量级），不是 K 和 V 本身。用的时候通过学好的升维矩阵还原出各头的 K，V。缓存量与头数无关，这是它能压得比 GQA 狠的原因。

**Q4：MLA 和 RoPE 为什么冲突，怎么解决？**
低秩压缩要求能把升维矩阵提前吸收进 Q 的投影里，而 RoPE 是位置相关的旋转，夹在中间无法被吸收。解法是把每个头的维度拆成两段：一小段照常做 RoPE 并直接缓存，其余部分走低秩压缩路径。

**Q5：三条路能一起用吗？**
能，它们分别作用在"头数""每头维度""层数"三个不同的轴上，互相正交。实践中是否全上取决于实现复杂度和目标场景，端侧模型往往叠得更狠。
